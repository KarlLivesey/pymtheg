# Third-party licences in the published package

Generated by `node scripts/licences/inventory.mjs --write` from `package-lock.json`,
the installed packages, the browser bundle's module graph and `grammars/*/manifest.json`.
`test/licences.test.mjs` fails when this file or `THIRD-PARTY-NOTICES` is out of date.
Do not edit by hand. This is an inventory, not legal advice.

The npm dependencies are as pinned by `package-lock.json`. A user's `npm install` of the
published tarball does not use that lockfile: npm resolves transitive dependencies afresh
within each package's version ranges, so a later install can receive newer versions (with
possibly different licences) than this inventory lists. The bundled, build-tool and
vendored code is fixed inside the tarball.

**Pymtheg is MIT licensed;** see `LICENSE`.

All shipped third-party components are declared under MIT, Apache-2.0, BSD-3-Clause or ISC. These licences permit redistribution inside an MIT-licensed package provided their notices are kept, which `THIRD-PARTY-NOTICES` does. Licences embedded inside some of those packages are listed below and travel in `THIRD-PARTY-NOTICES` with their packages' notices.

### tree-sitter-rust (grammar, built to grammars/rust/tree-sitter-rust.wasm)

- Upstream: https://github.com/tree-sitter/tree-sitter-rust, v0.24.2 @ 77a3747266f4d621d0757825e6b11edcbf991ca5
- Licence: MIT (file `grammars/rust/LICENSE`, reads as MIT)
- Copyright: Copyright (c) 2017 Maxim Sokolov
- built with tree-sitter-cli 0.27.2, wasi-sdk 34.0, binaryen version_132; imports its libc functions from web-tree-sitter at load time
- Patches applied before building:
  - `patches/0001-pr319-struct-pattern-field-attributes.patch` — https://github.com/tree-sitter/tree-sitter-rust/pull/319: Attributes (e.g. #[cfg]) on struct-pattern fields
  - `patches/0002-pr271-unit-struct-where.patch` — https://github.com/tree-sitter/tree-sitter-rust/pull/271: A where clause on a unit struct (`struct X where T: Eq;`)
  - `patches/0003-pr317-tilde-in-token-trees.patch` — https://github.com/tree-sitter/tree-sitter-rust/pull/317: The `~` token inside macro token trees
  - `patches/0004-pr312-le-after-cast.patch` — https://github.com/tree-sitter/tree-sitter-rust/pull/312: `<=` after a cast to a named type (`x as size_t <= y`)
  - `patches/0005-pr283-unicode-escape-underscore.patch` — https://github.com/tree-sitter/tree-sitter-rust/pull/283: Underscores in unicode escapes (`\u{4_e}`)
  - `patches/0006-pr281-extern-types.patch` — https://github.com/tree-sitter/tree-sitter-rust/pull/281: `type X;` (foreign types) in extern blocks
  - `patches/0007-own-raw-contextual-identifier.patch` — own patch (Pymtheg): `raw` is not a keyword: the raw-borrow marker is an identifier aliased to the anonymous node `raw`, only directly after `&` and before `const`/`mut`; `raw` is removed from `_reserved_identifier`. Fixes the v0.24.x regression where `raw` as a type name, generic parameter, item name or `raw @ pattern` failed the file; `&raw` on a variable stays a plain borrow and `&raw const`/`&raw mut` trees are unchanged
  - `patches/0008-own-safe-qualifier.patch` — own patch (Pymtheg): The edition-2024 `safe` qualifier (`safe fn` / `safe static` in `unsafe extern` blocks) as an identifier aliased to the anonymous node `safe`, only at the start of a body-less function signature or a static item; `safe` stays an ordinary identifier elsewhere (unlike upstream PR #256, which reserves it)
