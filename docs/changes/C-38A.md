# C-38A: the early claim also for modules reusing their analysis; the analysis path in the index report

Split from C-38 (pull request 50), which keeps the TypeScript scoped
re-index. This part needs no scoped path.

When this pull request was opened it also made an index run claim the store
before analysis. C-53 (pull request 63) has since merged a claim into main:
a run holding back edited files' writes until their module's analysis
writes its mark at the end of the parse write, so a run that begins during
the analysis takes over. C-53 leaves out modules that reuse their analysis
(C-27, C-36), so that a run stopped there leaves the previous graph
unmarked. That leaves the race open for them: the Go race test below fails
on main with this branch's other changes. This branch claims for those
modules too, and adds what main does not have.

## The claim for modules reusing their analysis

The condition in `indexer.ts` is now any module holding edited files,
reusing or not.

**Which statuses change against main.** A module reuses its analysis
(`reusing` in `indexer.ts`) when it declares `incrementalAnalysis` and the
store records a completed analysis of its current version: Go and Rust on
a re-index after a completed one. TypeScript does not reuse this way, and
C-53 already claims for it, so nothing changes for TypeScript.

For Go and Rust, a re-index stopped during their analysis (a signal, a
crash) now leaves the run's unfinished mark. Its stored rows are still
the previous complete graph's, as before. A `--no-sync` query
(`graph file … --no-sync`) then reports:

|            | Main (C-53) | This branch  |
| ---------- | ----------- | ------------ |
| `status`   | `ok`        | `incomplete` |
| `exitCode` | 0           | 2            |

`sync.complete` is `false` on both, with the `index-incomplete` warning.
A run stopped later (in resolution) was already `incomplete` on main. The
next index repairs either, and it is a full analysis: it finds the mark,
trusts no record and reuses nothing. The same holds after a takeover.
Reviewer A measured 20 Go packages with one edited: after an interrupted
re-index the next index reports `unchanged=0 indexed=20`, where it reported
`unchanged=19 indexed=1` before.

**Known limit, not fixed here.** A run paused in parse, before its claim,
can still write rows of a tree that has since been reverted. It is
reported `incomplete`, and the next index repairs it. C-36's two Rust signal tests
(`test/graph-rust-finishing.test.mjs`, analyze phase) assert the new
status.

## The analysis path in the index report

The index result's report gains `analysisPaths`: per module that reports
one, the path its analysis took, and the CLI prints it
(`Analysis typescript: full (no previous index)`).

- TypeScript reports `reused` when it builds no program (its stored
  results stand) and `full` otherwise. Without a scoped path (C-38) it
  never says anything else.
- The note `no previous index` means no run finished completely before
  this one. The store keeps that record (`index-completed` in its
  metadata) across later runs, including one that was taken over; per-file
  records cannot tell, since after a takeover every one looks new.
- A module reports a path only if it declares `reportsAnalysisPath` and has
  files in this index. TypeScript's analysis also runs with no files, and
  reported `reused` on every Go-only and Rust-only project until review
  round 2. It must analyse in this process, because a context cloned into
  a worker cannot carry the report function. Go and Rust do not report one
  yet.
- A real no-edit `graph index` (CLI or MCP) takes the verified shortcut
  (C-33): no module analyses, and the report has no `analysisPaths`. The
  test's `reused` case exists only because it injects its own module
  list, which the shortcut does not cover.

Tests, `test/graph-typescript-analysis-path.test.mjs`:

- a first index, an unchanged re-index (injected modules), an edit;
- through the real CLI, both the JSON report and the printed `Analysis`
  line: a Go-only and a Rust-only project, cold and after an edit, report
  no path;
- a TypeScript index after a run that claimed the store and stopped during
  analysis reports `full`, not `no previous index`.

## Race tests for the claim

`test/graph-index-runs.test.mjs` runs "Go: A analyses with an export
removed and pauses; it is restored; B completes; A resumes and writes
nothing". Go holds back its parsed writes until analysis, so without the
claim B found the store unchanged, answered without writing, and A then
wrote its stale analysis. With the claim for reusing modules, A rejects, the
rows equal B's, and one more index equals a cold index. With C-53's
condition alone A is not rejected ("Missing expected rejection"). "Rust:
A analyses with a function removed and pauses; …" is the same race for
Rust, and fails the same way under C-53's condition.

To reproduce the failure under main's condition, from this branch: in
`src/graph/indexer.ts`, restore C-53's condition for the claim,

```ts
if (
  [...deferred].some(([module, files]) => files.length && !reusing.has(module))
)
  await store.claimIndexRun?.();
```

then build and run the test:

```sh
npx tsc -p .
node --test --test-name-pattern="(Go|Rust): A analyses" test/graph-index-runs.test.mjs
# AssertionError: Missing expected rejection (both tests)
```

This branch, before its condition changed (local merge of main into it,
with C-53's condition), failed exactly so on the dev server.

No stored row changes, so no module version changes.
