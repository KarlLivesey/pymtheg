# C-3 TypeScript lexical declarations and workspace packages

Nested function declarations, function expressions and arrows assigned directly
to a local `const` or `let`, and local classes and enums now have graph symbols.
Their IDs use the existing file, scoped name, kind and same-name ordinal.
The scope is the nearest graph declaration, including named functions that
contain anonymous callbacks. Inserting an unrelated declaration keeps the IDs
of existing same-named siblings.

Plain local variables and parameters, including destructured bindings, use the
`lexical` kind. File, column-qualified, qualified-name and symbol-ID queries can reach
them. General text search and unqualified names exclude this kind. The graph
stores the first expression-use reference per enclosing graph symbol and
target binding, along with individual call sites. A local callable must have
a directly declared body and no detected reassignment. Calls through variables
holding unknown values or parameters stay unresolved, as do calls through
bindings that shadow an import.

The snapshot host supplies virtual install links from npm, Yarn and Bun
workspace manifests, pnpm workspace membership and dependency declarations,
and checkout-local `file:` and `link:` dependencies. TypeScript chooses the
actual module via the importing file's resolution mode, package entry maps,
configured paths or a project reference redirect. A compiler lookup for
missing build output is recorded as `workspace-build-output-missing`. Other
unavailable entries of known local installs are `workspace-entry-unavailable`.
Calls through a workspace import keep an unresolved runtime target when the
checker supplies only an interface signature.

The pnpm reader recognises the package-list block and relevant linking flag.
Dependency scenarios requiring lockfile or package-manager override evaluation
can remain unresolved. A conflicting declaration suppresses the corresponding
shared workspace link where the install layout cannot be established.
Indirect callable values, local class members, IIFEs, property-chain typing,
type parameters and library targets remain outside this change.

The TypeScript module version moves from 17 to 18, so existing stores reindex
these files. No runtime dependency or setting was added.

The comparison's T3 Code examples come from a different checkout than SW-3.
The regression fixtures cover those declaration and import shapes and the
pinned corpus's `SessionCredentialService.ts:476` example. The pinned T3 Code
workspace uses Bun.
