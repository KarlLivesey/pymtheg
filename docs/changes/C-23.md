# C-23 Remaining TypeScript links with dependencies installed

## Measuring the gap

The C-20 paired score was 70.42% bare and 80.28% installed on the 18 pins.
The census uses the installed populations and counts each stored TypeScript
link below Level 2 once. It groups by the stored reason and link kind.
A named checkout or library destination earns Level 2. Candidate sets and
unit-only library links stay below it.

The 200-site draw apportions places across reason and kind groups by their
link counts, rounds by largest remainder, and selects the smallest hashes
within each group at seed `pymtheg-c23-2026`. The source review uses the
pinned TypeScript compiler over each owning config and its captured
declarations. The audit distinguishes a compiler-selected declaration, a
merely typed callable value, and an apparent answer under an incomplete
configuration.

## Install availability

The Nest pin's contributor guide specifies `npm ci --legacy-peer-deps`.
The sweep applies that flag to that pin and disables lifecycle scripts.
Bun was unavailable on the dev server. T3 Code and Zod's `nub` installation
retain their bare figures.

The four targeted examples are outside the proportional sample. Excalidraw's
React default and tRPC's Zod namespace have provable bindings. The Dexie
`HTMLInputElement` type keeps a real augmentation from user-event even after
removing empty React declarations. The named workspace import uses a packed
local copy inside pnpm's store and has an unavailable entry. The archive
includes the source location, stored outcome
and checker declarations for each site. [Sample](../../evidence/c-23/gap-audit.json.gz)

On usable installs, an optimistic ceiling for the current sites and
metric is about 95.5%. This extrapolates the 34 intrinsically non-definite
sites and the 17 module-only sites across the measured 17.68% gap. Holding
the 64 configuration and build-input misses fixed lowers that estimate to
about 89.8%. These are sample-based planning estimates. The first assumes
that all other cases can be proved, including the uncertain group. The
second keeps current input availability and cross-config disagreements.
Neither includes additional gaps on pins that could not install.

## Changes

- For an installed import selected by the compiler, a module augmentation
  wrapper does not own the original export. Any actual member declared by
  that augmentation still uses its declaring package. This recovers the
  synthetic React default export in Excalidraw and tRPC.
- For a type reference, an empty installed DOM compatibility interface with
  identical, non-generic heritage adds no owner. A stub with another base,
  type parameters or a declared member can still contribute a candidate.
  Node's overlapping declarations keep the C-11 treatment.
- The installed declaration behind a named namespace re-export can prove the
  written binding even when the terminal compiler declaration is a source
  file. The package entry and terminal declaration must agree on their
  package, as in tRPC's `import { z } from 'zod'`.
- A captured package's physical workspace symlink can explain why its entry
  is missing. The graph reports `workspace-build-output-missing` when the
  compiler probes the configured output directory. It leaves the target
  unresolved until the checkout has an entry. A packed local dependency needs
  different provenance evidence to identify it with the checkout workspace.
- Installed packages can name a member written directly in the inline
  return type of a single exported factory. The link identifies its actual
  declaration, as with Astro's `checker.linter.getRootFileNames()` from
  `@volar/kit`. Mapped members without a declaration and overloaded
  factories with competing return shapes keep their existing outcomes.

The TypeScript analyzer version advances to 36 so existing stores re-index.
The code reuses the snapshot's resolver and checker. It adds no install
discovery walk or dependency execution.

## Remaining gaps

The largest sampled blocker is configuration and generated output. For
example, an installed declaration cannot make two Hono configurations agree
and cannot build Vitest's checkout workspace entries or Mermaid's parser.
Checkout callbacks, structural callable values and `any` need producer
evidence before they can be definite. A compiler recovery signature on an
invalid call is insufficient to select an overload owner. Some installed
packages, including Mermaid's Khroma use, still leave a named export
unavailable under the owning module-resolution settings. Unit-only import
sites and genuine runtime or declaration ambiguity remain below Level 2.
