# LIC-2: SPDX tags on first-party source files

Part 2 of the licence work ([LIC-1](LIC-1.md)). Items 1 and 2 of LIC-1's
part-2 list were already done by R1-H (PR 45): `package.json` has
`"license": "MIT"` (still `"private": true`), and `docs/licences.md` already
says "Pymtheg is MIT licensed; see `LICENSE`." This change does item 3 only.

## What is tagged

Each first-party source file starts with one line,
`SPDX-License-Identifier: MIT`, in its language's comment style: `//` for
TypeScript, JavaScript and Go, `/* */` for CSS, `<!-- -->` for HTML and `#` for
shell. After a shebang it is the second line; in `web/index.html` it follows
`<!doctype html>` (the one-line file is split after the doctype). In Go files
a blank line follows the tag so it is not part of the package doc comment, and
`//go:build ignore` in `golinks.go` stays in the file header, where Go reads it.
No copyright line, no licence text.

Scope, by rule: every file of a source kind under `src/`, `web/src/`,
`scripts/` and `test/`, plus `grammars/build.mjs`, `web/vite.config.ts`,
`web/index.html`, the root `pymtheg` launcher and any source file at the
repository root (none today). An extensionless file under those directories
that starts with a shebang counts as shell.

## Excluded, and why

- `web/src/generated/**`: generated by `scripts/schema.mjs` (`report.js`).
- `test/fixtures/**`: fixtures and sample projects that tests parse, index or
  copy as input; a tag would change the input. The directory also holds 14
  `.mjs` helper modules that tests import (for example
  `graph-go/harness.mjs`, `mcp-graph/controlled-worker.mjs`); they are left
  untagged with the rest of the directory, and
  `graph-core/reference/*.mjs` are frozen copies of earlier compiler output
  whose README says only import paths and formatting differ.
- `grammars/go/**`, `grammars/rust/**`: vendored third-party grammars, their
  patches and upstream `LICENSE` files.
- `examples/**`: example and scaffold material. LIC-1's plan had
  `examples/plugins/` tagged; this change's brief excludes all of `examples/`,
  so `examples/plugins/javascript.mjs` stays untagged (owner's call).
- `node_modules/`, `dist/`, `dist-web/`, lockfiles, JSON (including
  `tsconfig.json` and `web/tsconfig.json`), Markdown, `.pym` files (including
  `test.pym`), `assets/icon.svg`, `THIRD-PARTY-NOTICES`, `docs/`,
  `research/` and `evidence/`.

## Byte-exact checks

- No test hashes, snapshots or compares the text of a tagged file.
  `test/r1h-packaging.test.mjs` reads the first four lines of
  `src/cli/main.ts` for `import "./quiet-warnings.js"`; it is now line 4
  (shebang, tag, comment, import) and still inside that window.
- `golinks.go`: the helper binary is cached under a key from its source hash,
  so the tag changes the key and an existing installation rebuilds the helper
  once on its next Go index. `go build golinks.go` names the file, so
  `//go:build ignore` is still honoured as before.
- No first-line pragmas (`// @ts-check`, `@jsx`, `"use strict"`) exist in the
  tagged files; `web/src/generated/report.js` (which starts with
  `"use strict"`) is excluded anyway.
- `scripts/acceptance/**` is tagged. The self-test's sabotage anchors are all
  in `dist/` code and none matches the tag; one harness scenario was run (see
  the pull request). `scripts/gui-check.mjs` fingerprints sources only to
  compare a run against itself.
- The tags reach `dist/` (TypeScript keeps comments) and `dist-web/index.html`;
  the Vite build strips the CSS and script comments. The packed file list is
  unchanged.

## Tools

- `scripts/spdx-tags.mjs` adds the tags. It is idempotent (a second run
  reports `tagged 0 file(s)`); `--check` lists untagged files. Dropping the
  tags later is one revert of this change.
- `test/licence-tags.test.mjs` walks the scope by the same rules (its own
  copy, with the exclusions in one list, one reason each) and fails for any
  untagged in-scope file, and for a tag in `web/src/generated/`,
  `test/fixtures/` or the vendored grammars. A second case builds a small tree
  in a temporary directory and checks that the audit reports an untagged file,
  a tag below the first line, an untagged shebang script and a tagged fixture.
- `CONTRIBUTING.md` asks for the tag on new source files.
