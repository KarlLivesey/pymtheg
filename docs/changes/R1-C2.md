# R1-C2: requirement links over MCP

Two tools wrap the R1-D library: `requirement_links` (actions: requirement, add,
remove, refresh, list, check, requirements_for, unlinked, history), and
`link_result` (progress, pages, cancellation). Actions keep the intent explicit
without nine similar tool names; the second tool is only needed for long work or
additional pages. No resolution, fingerprint or impact algorithm is duplicated.
Selectors are passed unchanged to the library, including a literal graph
`symbol:<64 hex digits>` reference. Requirements are native planning records;
relationships record intent, not satisfaction/conformance evidence.

## Execution, limits and honesty

All library operations run in owned Workers. SQLite's synchronous 30-second lock
wait cannot block the MCP event loop. A request waits up to five seconds by
default, then returns either the first completed page or a running handle and
progress; wait:false opts out. link_result wait:true waits for worker exit.
Progress describes execution of the library action, not per-file index progress
(the library exposes no progress callback). Finish explicit graph indexing first
for large projects. Graph and link workers exclude each other within a connection.

One link job runs per connection; three immutable results are retained, each at
most 8 MiB of compact tables. Actual wire replies (text plus structuredContent)
are capped at 64 KiB. Pages default to 20/max 100, shrink by UTF-8 bytes, and carry
totals, offsets, nextOffset and truncation. Unlinked symbols separately default
to 200/max 1,000; core truncation needs a new query. Names/messages are explicitly
clipped at Unicode boundaries; paths/IDs are kept exact. A single oversized row
or retained result is refused with guidance, never an incomplete success. Global
metadata can itself exceed a bound; fixing/narrowing the project can be necessary.

Disconnect and cancellation join owned workers. Native SQLite may need to return
before termination completes; other MCP requests can still run. Cancellation
cannot undo a committed planning write: replies instruct the agent to reconcile
list/unlinked/history/planning records before retrying. No automatic mutation
retry occurs. Missing/expired handles give actionable errors. A killed mutation
has an explicitly unknown commit outcome, not a rollback promise.

Check results put non-ok/orphaned rows first, with differences, suggestions,
named unverifiable files and next actions in the first page. Ambiguous adds put
matches in the default page and create no link. A failed path selected by a
selector/file query is the first failed-file preview, with all other failures
paged. Suggestions are never applied. Moved remains unconfirmed until refresh;
allowMoved is explicit. passed is false if the library fails or graph coverage is
incomplete, failed, stale or warned; libraryPassed preserves the narrower library
verdict. A completed worker/index is not a proof or an all-good verdict.

requirements_for follows only definite callers, preserving the library's impact
bounds, incomplete flag, notFollowedCount and candidate/possible caller names in
a separate section. Unlinked queries show both requested directions in the
default page, with separate symbol pages too. Stored code-link internals (including
history journals and raw fingerprints) are not expanded into agent replies.

## Four R1-D fixes

- At link AND refresh, twins is null if any failed/partial source of that language
  exists. Refresh rechecks twins even for otherwise unchanged code; an explicit
  refresh can invalidate or re-establish continuity metadata. Repairing a hidden
  file later cannot turn a previously uncertain snapshot into a proven move.
- Refresh retains the prior CodeSymbolRef keyed by the exact previous receipt
  content hash in an optional pathHistory field of the existing link JSON body.
  No schema/store boundary change. History joins receipt hashes to those refs,
  so repeated moves, body refreshes and removal retain their actual paths. The
  actual row body at write time is paired with its hash, including when another
  writer intervenes during graph sync. The original immutable key establishes
  the initial path. Older intermediate bodies
  (or a lost concurrent history branch) cannot be reconstructed from hashes alone:
  pathKnown:false and `[historical path unavailable]` are explicit, never today's
  path. Journals grow with refreshes; archive export still does not carry links.
- Rust's attribute scanner recognizes a raw string only with an opening quote
  after its hashes. r#ident no longer forces a fallback that can miss cfg across
  blank lines.
- Go directives span blank lines above the declaration, bounded by the previous
  declaration/non-comment code. Enclosing/file-level attributes remain outside a
  member's fingerprint, as documented by R1-D. The exact whitespace/text rule is
  unchanged. R1-D's rule text was updated; no other architecture source changed.
