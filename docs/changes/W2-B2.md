# W2-B2: fixes to the merged Go module

Follow-up to W2-B (PR 12, merged at `7dfb346b`). A second-model review of the
merged module found three defects. This chunk fixes them, and one cheap
backlog item. The contract is unchanged (`docs/changes/W2-B.md`, and the
rulings in `docs/build-plan.md`). Module version 21.

## 1 and 2: redundant parentheses (one fault)

Go allows redundant parentheses around a type and around an expression. The
module did not look through them consistently:

- **A wrong definite link.** In `func (F (Fn)) M() { F() }`, the receiver was
  recorded as `(?).M` and its variable was not declared. So `F()` was linked
  definitely to the package-level `func F`, but Go calls the receiver variable.
- **A lost implementer and dispatch target.** `type W (struct{ A })` lost its
  embedded field. So `W implements I` was missing, and dispatch on `i.M`
  omitted `A.M` promoted through `W`.

**The fix is in one place.** Every child the extractor reads now goes through
`named`, `fieldOf` or `fieldsOf` (`extract.ts`), which look through redundant
parentheses. No switch on a node's type in `extract.ts` can see a
`parenthesized_type` or `parenthesized_expression` with a single child.

**Audit.** Before the fix, these sites switched or branched on a node's type
and could see a parenthesised node read raw through `childForFieldName`. All
now read through the helpers:

- the receiver (`method`: receiver type, pointer, generic base, name);
- parameter, result and field declarations (`parameters`, `resultDescs`,
  `structFields`, the embedded-field branch);
- `typeTerm`, `typedValue` and `typeRef`, which unparened only at their own
  entry and not the children they read (`element`, `value`, `key`, `result`,
  `type`);
- type declarations (`type W (struct{…})`, `type I (interface{…})`, `type A =
(T)`: the `struct`/`interface` kind and the shape were decided on the raw
  node);
- expression descriptions (`selector_expression`, `call_expression`,
  `index_expression`, `unary_expression`, `type_conversion_expression`
  operands);
- every call, assignment and declaration walker.

`resolve.ts` reads no syntax tree; it works on the extracted descriptions and
terms, so it has no such site.

**Which forms are legal Go** (checked with `go build`, Go 1.27.4):

- **Legal:**
  - receivers `(T)`, `(*T)`, `*(T)`, named and unnamed;
  - parameters and results `(T)`, `*(T)`, and named results;
  - fields `(T)`;
  - `[](T)`, `map[(K)](V)`, `chan (T)`, `func((T)) (T)`;
  - `type W (T)`, `type W (struct{…})`, `type I (interface{…})`, `type A =
(T)`;
  - `(G[int])`;
  - conversions `(T)(x)` and `((*T))(nil)`;
  - method expressions `(T).M` and `((*T)).M`;
  - operands `(x).M()`, `((*p)).M()` and `((&v)).M()`;
  - the callee `((F))()`.
- **Not legal:**
  - parenthesised embedded fields: `struct{ (T) }`, `struct{ *(T) }` and
    `struct{ (*T) }` ("cannot parenthesize embedded type");
  - a parenthesised composite-literal type: `(T){}` ("cannot parenthesize
    type in composite literal").

  The grammar accepts both, so such a file is valid here. That is the
  existing known limit for Go text the grammar accepts but the compiler
  rejects.

**Test:** `test/graph-go-parens.test.mjs` has a matrix of the 23 legal cases.
Each gives the same graph with and without the parentheses (symbols, links,
targets, candidates and data, up to source offsets). There are also explicit
assertions for both review repros.

## 3: an anonymous struct's named field took an unrelated failed-file cause

Take `var S struct{ p.T; B *bytes.Buffer }`, with a broken `p/bad.go`.
`S.B.Write(nil)` became `invalid-code` blaming `p/bad.go`, although `B` does
not depend on `p.T`. The same happened for `mk().B.Write(nil)`.

**Why.** The round-16 guard (a named field follows only its own type) worked
only when the anonymous struct was written in the expression itself or in a
local. Through a package variable, a call result, or a field of another struct,
the backstop did not find the struct. `select` also returns a field as its
value type and drops its declaration.

**The fix.** The backstop now finds a value's written type through every route,
and asks `select` for a selected field as its symbol. The routes are:
variables, names (package variables, parameters), selected fields, call
results, func values, and container elements. The selected named field's own
type is used before any embedding is considered. Resolution itself is
unchanged.

**Test:** `test/graph-go-anonymous.test.mjs` reaches a value of type `struct{
p.T; B *bytes.Buffer }` by 16 routes. They are: package variable, local
variable, local with its address taken, parameter, result, func-value result,
field of another struct, array, slice, map and channel element, range value,
pointer, alias, composite literal, and conversion. On each route:

- `.B.Write` is plainly unresolved, with `bad.go` broken or fixed;
- `.M()`, which only the embedded `p.T` can supply, is `invalid-code` with
  cause `p/bad.go`.

It also covers the reviewer's two repros, and the earlier review's backlog
cases: `type W = struct{ F p.T; bytes.Buffer }`, where `w.Write` stays plain;
and `type MT = map[p.T]time.Time`, where a range value stays plain.

## Backlog: name-only sets

A name-only set (unknown receiver) now carries `declarations-may-be-unseen`
when a failed or untrusted file could declare a method of that name: for an
exported name, any such file; for an unexported one, only one in the caller's
package. Tested with controls.
