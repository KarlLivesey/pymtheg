# W2-B2: fixes to the merged Go module

Follow-up to W2-B (PR 12, merged at `7dfb346b`). A second-model review of the
merged module found three defects. This chunk fixes them, and one cheap
backlog item. The contract is unchanged (`docs/changes/W2-B.md`, and the
rulings in `docs/build-plan.md`). Module version 22.

## 1 and 2: redundant parentheses (one fault)

Go allows redundant parentheses around a type and around an expression. The
module did not look through them consistently:

- **A wrong definite link.** In `func (F (Fn)) M() { F() }`, the receiver was
  recorded as `(?).M` and its variable was not declared. So `F()` was linked
  definitely to the package-level `func F`, but Go calls the receiver variable.
- **A lost implementer and dispatch target.** `type W (struct{ A })` lost its
  embedded field. So `W implements I` was missing, and dispatch on `i.M`
  omitted `A.M` promoted through `W`.

**The fix is in one place.** Every child the extractor reads now goes through
`named`, `fieldOf` or `fieldsOf` (`extract.ts`), which look through redundant
parentheses. No switch on a node's type in `extract.ts` can see a
`parenthesized_type` or `parenthesized_expression` with a single child.

**Audit.** Before the fix, these sites switched or branched on a node's type
and could see a parenthesised node read raw through `childForFieldName`. All
now read through the helpers:

- the receiver (`method`: receiver type, pointer, generic base, name);
- parameter, result and field declarations (`parameters`, `resultDescs`,
  `structFields`, the embedded-field branch);
- `typeTerm`, `typedValue` and `typeRef`, which unparened only at their own
  entry and not the children they read (`element`, `value`, `key`, `result`,
  `type`);
- type declarations (`type W (struct{…})`, `type I (interface{…})`, `type A =
(T)`: the `struct`/`interface` kind and the shape were decided on the raw
  node);
- expression descriptions (`selector_expression`, `call_expression`,
  `index_expression`, `unary_expression`, `type_conversion_expression`
  operands);
- every call, assignment and declaration walker.

`resolve.ts` reads no syntax tree; it works on the extracted descriptions and
terms, so it has no such site.

**Which forms are legal Go** (checked with `go build`, Go 1.27.4):

- **Legal:**
  - receivers `(T)`, `(*T)`, `*(T)`, named and unnamed;
  - parameters and results `(T)`, `*(T)`, and named results;
  - fields `(T)`;
  - `[](T)`, `map[(K)](V)`, `chan (T)`, `func((T)) (T)`;
  - `type W (T)`, `type W (struct{…})`, `type I (interface{…})`, `type A =
(T)`;
  - `(G[int])`;
  - conversions `(T)(x)` and `((*T))(nil)`;
  - method expressions `(T).M` and `((*T)).M`;
  - operands `(x).M()`, `((*p)).M()` and `((&v)).M()`;
  - the callee `((F))()`.
- **Not legal:**
  - parenthesised embedded fields: `struct{ (T) }`, `struct{ *(T) }` and
    `struct{ (*T) }` ("cannot parenthesize embedded type");
  - a parenthesised composite-literal type: `(T){}` ("cannot parenthesize
    type in composite literal").

  The grammar accepts both, so such a file is valid here. That is the
  existing known limit for Go text the grammar accepts but the compiler
  rejects.

**Test:** `test/graph-go-parens.test.mjs` has a matrix of 26 legal cases,
including triple nesting, `case (T):` and `case (*T):` in a type switch, and an
embedded `interface{ (I) }`.
Each gives the same graph with and without the parentheses (symbols, links,
targets, candidates and data, up to source offsets). There are also explicit
assertions for both review repros.

## 3: an anonymous struct's named field took an unrelated failed-file cause

Take `var S struct{ p.T; B *bytes.Buffer }`, with a broken `p/bad.go`.
`S.B.Write(nil)` became `invalid-code` blaming `p/bad.go`, although `B` does
not depend on `p.T`. The same happened for `mk().B.Write(nil)`.

**Why.** The round-16 guard (a named field follows only its own type) worked
only when the backstop could see the anonymous struct, written in the
expression itself or in a local. Through a package variable, a call result, a
field of another struct, a callable value, a builtin, or a named or aliased
type, it could not:

- `select` returns a field as its value type and drops its declaration;
- the walk then followed the struct's embedded types for the member, even
  though the member was one of its own named fields.

PR 19's two reviews (Sol, then Opus) found further routes after the first fix.
This section describes the fix as it now stands.

**The fix has two layers.**

1. **The safety net, used whatever the route.** Wherever the backstop's walk
   reaches a struct or interface, as an anonymous value or as a type term
   (an alias's target), it checks the member first. A member that is one of
   the struct's own named fields, or one of the interface's own methods, is
   found at depth 0. Then nothing the struct or interface embeds is followed.
   If the selected field's own type cannot be recovered, the link stays
   plainly unresolved: the conservative answer, which never names an
   unrelated cause.
2. **Recovering the selected field's own type**, so that a named field of a
   failed type still gets its certain cause. The backstop works out a
   value's written type through these routes, and no others:
   - local variables (also with their address taken), parameters and package
     variables (one declaration; with build variants it gives up);
   - a selected field: of an anonymous struct, through its own fields; of a
     named struct, through the field's declaration (`select` is asked for the
     field symbol, a backstop-only option, so resolution is unchanged);
   - elements and keys of slices, arrays, maps and channels, and range values;
   - calls of:
     - declared functions and methods, including method values and method
       expressions, for any result index;
     - function-typed variables, parameters and fields;
     - elements of containers of functions;
     - function literals called in place;
     - results of function type (`mkf()()`);
     - named and aliased function types, through their declaration, also
       over another named function type;
   - the builtins `new`, `make` and `append` (their hint, as `desc` reads it);
   - named and aliased types written as a literal (`type SA = []struct{…}`,
     `type NS []struct{…}`). The extractor now keeps a value description
     (`data.v`) on such a declaration;
   - composite literals and conversions to an anonymous type;
   - a call whose callee is not described (`(<-fc)()`), read as "call what is
     written".

   **Anything else** falls back to layer 1. That includes several
   declarations of one name (build variants), generic instantiation (type
   arguments are not followed), and any expression form not listed. The
   named-field control is then still plain, and only a cause that the walk
   can show may be lost.

**Tests:** `test/graph-go-anonymous.test.mjs`. On every route there are three
checks:

- `.B.Write` is plainly unresolved, with `bad.go` broken and fixed;
- `.M()`, which only the embedded `p.T` can supply, is `invalid-code` with
  cause `p/bad.go`;
- `.F.M()`, where `F` is a named field of type `p.T`, is `invalid-code`.

The routes:

- **16 to an anonymous struct value:** package variable, local variable,
  local with its address taken, parameter, result, func-value result, field
  of another struct, array, slice, map and channel element, range value,
  pointer, alias, composite literal, and conversion.
- **17 callables:** package-level and local function variables, a variable
  holding a declared function, a function parameter, named function types
  (also over a named function type), a function-type alias, package-level
  slices and arrays, maps and channels of functions, a function-typed field,
  a function-typed result, a literal called in place, a method, a method
  value, and a method expression.
- **10 more routes:** `new`, `make` and `append`; named and aliased function
  types; an alias of a slice type; a defined slice type; a local initialised
  from `new`; a second result; and a map key in `range`.

Two tests pin the fallback, using build variants that `written()` refuses:

- a function variable (layer 1 on the anonymous value);
- an alias of a slice (layer 1 on the type term).

The file also covers both reviewers' repros, and the earlier backlog cases:
`type W = struct{ F p.T; bytes.Buffer }`, where `w.Write` stays plain; and
`type MT = map[p.T]time.Time`, where a range value stays plain. Every fixture
passes `go build ./...` (and `go vet` for the callable and later routes) with
the failing line removed.

The interface half of the term guard (an alias of an anonymous interface,
reached only through its type term) mirrors the struct half. It has no test
of its own.

## Backlog: name-only sets

A name-only set (unknown receiver) now carries `declarations-may-be-unseen`
when a failed or untrusted file could declare a method of that name: for an
exported name, any such file; for an unexported one, only one in the caller's
package. Tested with controls.

## Known gaps recorded, not fixed here

- **Grammar gap.** Valid Go `func F() { f := func() {; G() }; f() }` (an
  empty statement right after `{`) fails the whole file, with "syntax error in
  line N: unexpected `G`". `gofmt -e`, `go build` and `go vet` accept it.
  Tree-sitter's grammar rejects it, so by the failed-file rule the file fails.
- **Logged by the round-1 Opus review, for later:**
  - causes lost (never wrong) through a generic `G[ST]` field and a generic
    `Id(s)`;
  - the same reason marking (G3) over-inclusive for a failed `_test.go` in
    another package;
  - an anonymous interface parameter `j interface{ I }` does not list `I.M`.

  The review also logged named slice, map, chan and array types and range
  over a named slice. Those now recover their element through `data.v`
  (above).
