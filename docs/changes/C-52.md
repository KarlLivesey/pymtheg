# C-52: The two defects SW-7 found on microsoft/TypeScript

SW-7 measured microsoft/TypeScript as a 20th installed TypeScript pin at
70.63% Level 2. Two defects held it down:
- **`taint-budget-exhausted`:** 138,422 links, 27.3 points of the pin;
- **placeholder results:** 8,409 of its 12,477 failed files stored with the
  indexer's "Awaiting project analysis" placeholder.

TypeScript module version: provisional (assigned at merge).

## (a) `taint-budget-exhausted`: diagnosis

The failed-file walk (`taint.ts`, C-13) is computed **once per program**,
not per link. A per-checker memo holds it, and every link of the program
reads the same answer. It finds which declarations depend on a failed file:
- **seeds:** every node of every valid file;
- **references:** what each declaration's parts refer to;
- **fixpoint:** a worklist that spreads causes (sets of failed-file paths)
  along the dependence edges.

The budget counts steps: nodes visited, edges followed, and causes stored,
compared or copied. Before C-52 it was a fixed 8,000,000 per walk. A walk
that met it, or a stack limit anywhere inside it, made the whole program's
taint unknown, and `index.ts` (`withoutTaint`) then reported **every link of
every file of that program** as `taint-budget-exhausted`.

A probe of the real pin ([walk-probe.mjs](../../evidence/c-52/tools/walk-probe.mjs)
with observation counters in `taint.ts`) on main `59e853b`
([probe-main.json](../../evidence/c-52/probe-main.json)):

| | |
| --- | --- |
| Walks | 14: two programs of about 14,480 files, rebuilt as files fail |
| Declarations read | 231,589 |
| Dependence edges | 17,983,363 |
| Walks stopped by a stack limit | 10, after 3.3–4.5 million steps, all in the references phase |
| Walks stopped by the budget | 4, at 8,000,001 steps, in the fixpoint |
| Steps spent storing and copying causes | up to 4.7 million of the 8 million |

There are three causes, and the first two are the cliff:
1. **One stack limit ends the program's walk.** The compiler ran out of
   stack answering a question about one declaration of the test corpus,
   whose stress tests are deep expressions. The walk turned that into
   "unknown" for the whole program.
2. **A fixed budget below a linear walk.** The walk is linear in its
   dependence graph (each edge is followed once per growth of its source),
   and that graph has 18 million edges. No fixed budget fits every program.
3. **Cause sets grow with the number of failed files, not with what a
   receiver can reach.** These programs contain no failed file of their
   own. Their causes come from unresolved names that thousands of failed
   test scripts declare (UNREAD_NAMES). One name can stand for hundreds of
   failed files, and every merge copied the whole set, a step per file. This
   is why the cost scaled with the failed files.

## (a) The change

- **A stack limit is contained to one declaration.** The checker's
  questions in the seeds and in each declaration's references are each
  contained. A stack limit there marks only that declaration's symbol with
  an unknown cause (`UNKNOWN_CAUSE`), which spreads through the fixpoint
  exactly like a failed file: whatever depends on that declaration is
  unknown, and nothing else. A link whose only cause is unknown is
  `taint-budget-exhausted`, with no target. One whose causes also name a
  real failed file is `invalid-code` with those (`withoutUnknownCauses`,
  `index.ts`). The seed traversal is iterative, so a deep expression cannot
  exhaust the walk's own stack. A limit while finding a declaration's symbol
  still makes the walk unknown, as before.
- **The budget grows with the dependence graph:** the base 8,000,000, plus
  4 steps per edge (`EDGE_STEPS`), once the references are read. A walk
  linear in its graph finishes; the budget is a backstop against superlinear
  cause growth only.
- **Cause sets are capped at 8 failed files** (`CAUSE_CAP`): the first the
  walk reaches, in walk order, which depends only on the snapshot. A full
  set never grows, so a merge costs at most 8 steps, and the fixpoint stays
  linear. Taint itself (whether a symbol has any cause) is unchanged.
  - A link reached through the walk names at most 8 of its failed files.
    A direct lookup of an unread name still names every file that declares
    it.
  - A cap of 64 exhausted Node's default heap on the pin. A finished walk
    holds one set per tainted symbol, about 231,000 there.
- **Soundness:** a link whose receiver depends on a failed file keeps its
  named reason (`invalid-code` with the file). A link that depends on a
  declaration the walk could not read is withheld (`taint-budget-exhausted`).
  Only links that depend on neither are answered.

### How this relates to C-47's judge budget (PR 58)

C-47 bounds the structural judge (`judge.ts`), which runs per link and
asks whether a receiver's type reaches a failed file at depth, with its own
per-checker budget and the reason `judge-budget-exhausted`. The judge reads
the walk's answer (`taint.all`, `taint.weak`) and refines it per link.
The two budgets are independent:
- **The walk's budget** is per program. Before C-52, meeting it withheld
  every link of the program. After C-52 it grows with the program's graph.
- **The judge's budget** is per checker and bounds the judgement of links
  the walk leaves open.

C-52 does not touch `judge.ts` or the lines PR 58 changes. Its only import
in `index.ts` is on a separate line.

## (b) "Awaiting project analysis"

The placeholder is what the indexer stores for a file before its module's
project analysis answers. An analyse-only module must answer every
readable file it is given, or the indexer throws. So a stored placeholder
means the module handed the stored input back as the file's result.

The same pin, indexed on current main `59e853b`, two ways:

| Run | Failed files | Holding the placeholder |
| --- | ---: | ---: |
| SW-7 (PR 51's pre-merge head `a95a346`, the sweep's CLI index) | 12,477 | 8,409 |
| Main, `indexProject` with the TypeScript module | 12,477 | 0 |
| Main, the CLI's `graph index` (all modules, as the sweep runs it) | 12,477 | 0 |

On main every one of the 12,477 carries a named cause: their own syntax
errors, such as "Type annotations can only be used in TypeScript files" for
the baseline `.js` files that concatenate a TypeScript source and its
emitted output, and "Expression expected" for deliberate negative tests.
So the 8,409 came from PR 51's head before it merged with main. Which change
in the merge removed them was not pinned down.

The rule is now enforced, so the placeholder cannot return:
- If an analyse-only module answers a file with the placeholder, the
  indexer stores a named failure instead: "The <module> module returned no
  result for this file (a defect in pymtheg, not a problem in this file; it
  is retried on the next index)". It is transient, so it is retried.
- The report lists it in `analysisErrors`.

Tested in `test/graph-analysis-placeholder.test.mjs`, which fails on main.
No file of the pin becomes indexed by this: none of the 8,409 is
placeholder-stored on main, and all carry their true syntax causes.

## Tests

- `test/graph-typescript-large.test.mjs`:
  - **The budget grows with the dependence graph:** an `extends` chain of
    300 interfaces over a failed file. Under a budget that covers reading
    the program but not the fixpoint, the walk finishes, the program's
    other links are answered and the chain's call keeps `invalid-code`.
    It fails on main, where every link was `taint-budget-exhausted`.
  - **A stack limit on one declaration:** a `RangeError` is injected into
    the checker for one interface while the walk reads it. Links through
    it are `taint-budget-exhausted`, the rest of the program is answered,
    and links into the failed file keep their cause. It fails on main.
  - **Cause sets of at most 8:** 12 failed scripts declaring the same
    interface, reached through a declaration that extends it. The call
    names 8 of them. It fails on main (12).
  - The existing budget tests (1 and 5 steps) still withhold the program's
    links: the budget is still a backstop.
- `test/graph-analysis-placeholder.test.mjs`: the placeholder becomes a
  named, transient failure and an analysis error.
