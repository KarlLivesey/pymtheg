# C-57: module files chosen by `cfg_attr(path)` are conditional

A second review of main found four wrong results with one root: a module
whose file `cfg_attr(…, path = "…")` attributes choose was treated as if
every alternative file were present at once.

```rust
#[macro_use]
#[cfg_attr(feature = "fast", path = "fast.rs")]
#[cfg_attr(not(feature = "fast"), path = "slow.rs")]
mod choice;
```

## What was wrong

1. **A macro both files define had one definite target.** The parser kept
   the alternative file names and dropped the predicates that select them.
   The textual macro lookup then took the first definition it met as
   present in every build. `pick!` resolved to `slow.rs`'s definition,
   although a build with `--features fast` uses `fast.rs`'s.
2. **A name such a macro could shadow went to std.** The C-34 shortcut
   bounds a macro's output when its one definition emits only fixed impl
   items. It took `slow.rs`'s `pick!` (an impl) as that one definition, so
   `Option` was not shadowed and resolved to `std::option::Option`. With
   `fast`, `pick!` defines the crate's own `Option`.
3. **An edit could differ from a cold index.** Macros a `#[macro_use]`
   module brings in were ordered by their offsets in their own files, so
   the two alternative files were compared by absolute offsets. A comment
   that moved `fast.rs`'s macro past `slow.rs`'s changed the cold answer,
   while the incremental index (whose fingerprints rank offsets within a
   file only) kept the old one: one file row and five link rows differed.
4. **A failure was cited from a file that cannot apply.** A call inside a
   `#[cfg(feature = "fast")]` function, into the module, was marked
   `invalid-code` citing `slow.rs`, which is never the module where the
   call exists. Parse failures were checked before the module's files were
   filtered by whether they can apply.

## The rule

A module file chosen by cfg carries its predicate, and everything declared
in it is conditional under that predicate.

- The parser records each alternative with its predicate
  (`pathAlternatives`: the path and the guards of its `cfg_attr`).
- The resolver adds the predicate to the conditions of the place that file
  gives the module. A file two alternatives name takes their disjunction;
  the plain module file, when the checkout has one, takes the negation of
  all of them (it is the module only when none applies). An unconditional
  `#[path]` stays as before.
- Macros a `#[macro_use]` module brings in carry the predicate of the file
  they come from. A macro two exclusive files define is then two
  conditional candidates: never one definite target, and so never the one
  definition C-34's shortcut needs (the name stays guarded by
  `opaque-item-may-shadow-name`).
- Entries from different module files are ordered by the file they come
  from, never by their offsets: no offset in one alternative decides
  against another.
- A failed module file whose conditions cannot hold together with the
  access's own is neither searched nor cited. Readable files are not
  filtered: a first version filtered every destination that way, and on
  helix it took away the proof that `bitflags!` in `helix-stdx/src/faccess.rs`
  cannot define std prelude names (74 links left Level 2; found by the pin
  comparison and bisected to that filter).
- A site is looked up only in its file’s places where its own conditions
  can hold. A file both alternatives declare (embassy-nrf’s
  `usb/vbus_detect.rs`, declared by `pub mod vbus_detect;` in both
  `usb/mod.rs` and `usb/usbhs.rs`) has a place under each predicate, and a
  site inside `#[cfg(feature = "_nrf54lm20-app")]` exists in only one. The
  library lookup asked every place and needed them all to agree, so in a
  `no_std` crate (core’s prelude) the impossible place spoiled `Ok`,
  `Err` and `AtomicBool`: five std links left Level 2 on embassy. The same
  rule applies to the checkout lookup and the core-method lookup, and to
  any file with several places, such as inline modules of one name under
  opposite cfgs (helix-stdx’s three `mod imp`, redb’s two `mod hash`).
  With no possible place, all are kept.

## Tests

`test/graph-rust-cfg-attr-path.test.mjs` has one test per fault, each on
the review's fixture shape, and one for the embassy shape. All five fail on
main (b6fd7c91) and pass here:

- `pick!` is not resolved to one definition;
- neither written `Option` is a library target in std;
- after a comment moves `fast.rs`'s macro past `slow.rs`'s offset, the
  incremental index's rows equal a cold index's, table by table;
- the call in the `fast`-only function cites no failure from `slow.rs` and
  resolves to `fast.rs`'s `pick`;
- in a `no_std` crate, `Ok` and `Err` inside `#[cfg]` blocks of a file both
  alternatives declare are core library targets (this one fails without
  the place rule and passes with it).

The seeded differential fuzzer (C-36) has a new shape,
`cfg-attr-path-macro`: a `#[macro_use]` module chosen by two `cfg_attr`
paths whose files define `pick!` differently, with edits that add or remove
a long leading comment in either file. A run of 1,000 seeded edits at seed
5701 (50 workspaces, 27 of them with the new shape, 49 edits moving an
alternative file's offsets) found no difference between an incremental and
a cold index. The suite's fixed-seed run includes the shape too.

the same project id and compared link by link (`evidence/c-57/compare-pins.sh`,

Embassy also has 4 new links (the expansion of `impl_vpr!`, now read
through the chosen file). The gains elsewhere come from the place rule:
redb’s `HashMap` and `BuildHasherDefault` in the std `mod hash` of
`fast_hash.rs`, clap’s `Self::Owned` in its cfg-gated `os_str.rs` and
`str.rs` modules, tauri’s Windows helpers in `util.rs`, actix-web’s
`HickoryDnsResolver`, crossbeam’s `FnOnce` and `Debug` in
`crossbeam-epoch`. Helix’s two changes are `chown` calls in
`helix-stdx/src/faccess.rs` that go from unresolved to a candidate set
holding the call’s real target.

## Limits

- An unconditional `#[path]` beside `cfg_attr` alternatives is handled as
  before (the unconditional path is the module).
- Inline modules chosen by `cfg_attr(path)` directories are unchanged.
