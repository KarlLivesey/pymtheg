# C-8: Go member links through call results, pointer conversions and local modules

Support items `go-factory`, `go-local-method`, `go-typed-reference` and
`go-pointer-conversion` in the coverage plan. Go module version 28 → 29: the
parser now records how many `*` a conversion's callee has (`Desc`
`unknown.p`), so stores built by an older version re-index. The opt-in
toolchain helper (`golinks.go`) changed too; it is rebuilt from its source
hash.

## What was already there

Member links through the results of checkout functions and methods were
already resolved on `main`: `x := pkg.New(); x.M()`, `v, err := f()`,
chains (`a.B().C()`), results stored in locals and struct fields, func-typed
fields and parameters. The plan's first example for `go-factory`, cilium
`fd.File("perf-event")` after `fd, err := pi.fd.Dup()`, was settled by C-4's
per-variant selection. A diagnostic pass over all 20 Go pins (a temporary
hook, not committed) sorted every member link whose receiver chain has a
call and that was not definite on `main`:

- About two thirds end in a type outside the checkout (cobra, fasthttp,
  `big.Rat`, a promoted method of an embedded library mock such as cli/cli's
  `pm.RegisterConfirm`). Those are library targets, a later chunk; nothing
  here touches them.
- About a sixth end in an interface-typed result: a dispatch candidate set
  by the module's interface rule, unchanged.
- About 5% are results of a type parameter's type (`T`). Nearly all of
  them (fiber's 4,700) come from `apptest.Ctx(t, New())`, where `C` is
  inferred through the interface `CtxPool[C]` and is itself an interface,
  so even a correct inference would give a dispatch set. Explicit
  instantiation with a checkout type (`As[*Fwd](x)` in cilium, about 300
  links across cilium, pebble and golang/tools) would need the type
  arguments stored at parse time; not built (below).

What remained, and what this chunk changes, was mostly not about return
types but about where a package or type is: a module joined by a bare `..`
replace, packages under `testdata`, a module under a dot directory, and the
`(*T)(x)` conversion syntax.

## What changed

**Imports resolve as the go command resolves them.** The import rules were
checked case by case against Go 1.27.4 (`evidence/c-8/go-import-rules.sh`,
output beside it). The modules that may provide an import path's package are
the main modules (the importer's module, or the `use`d modules of its
go.work) and the modules they require, each through its replacement:

- a `replace` of a module that is not required does nothing (Go: "replaced
  but not required"); before module graph pruning (go < 1.17) a dependency
  may still require it, so it is then a possibility, never proven;
- a local replacement (`./x`, `../x`, and `.` and `..` as
  `modfile.IsDirectoryPath` reads them; before, a bare `..` was not local)
  counts only when its directory has a captured go.mod (Go fails reading it
  otherwise; a go.mod declaring another module path still builds);
- a package is there only when it has a file Go can build ("build
  constraints exclude all Go files" otherwise), with `ignore` never set;
- two modules that both have the package are an ambiguous import, which Go
  rejects: the import is unresolved with `import-destination-uncertain`, and
  names through it are not followed. Before, the longest matching
  replacement won, so an unrequired `replace` of a path the main module
  provides moved the link to the replacement.

A replacement written `../` that names the checkout root
(bubbletea's `examples/go.mod`: `replace charm.land/bubbletea/v2 => ../`) is
the root directory `""`; `joinDirectory` returned `"."` for it, which the
go.mod check did not match (found by the full candidate run; fixed, with a
test).

gopls declares `require golang.org/x/tools` and
`replace golang.org/x/tools => ..` with a go.mod at the root, so every gopls
import of a golang/tools package now resolves.

**Packages under `testdata`, `_x` and `.x` directories are imported like
any other.** The resolver dropped every import destination with such a
directory element, documented as "imports Go forbids". Go skips those
directories only when it expands `./...` patterns; an explicit import of
one builds (checked with Go 1.27.4: a `testdata`, an `_x` and a `.x`
package of the main module, and a module whose root is under a dot
directory, all build). protobuf-go's generated test packages under
`cmd/protoc-gen-go/testdata/` import each other this way, and cli/cli's
`.github/skills/cli-exercise/tool` and `.github/codeql/tests/…` modules
import their own packages. A GOPATH-style import inside testdata
(`import "b"`) is still no module path and stays unresolved.

**Pointer conversions.** `(*T)(x)` and `(*p.T)(nil)` were calls whose
callee is not described, so their `calls` link stayed unresolved. When what
is written in the callee names a type, the link now goes to that type, as
`T(x)` already did (build variants of `T` give their usual set). A callee
naming anything else (`(*fp)()`, a pointer to a func value) stays
unresolved. The value of `(*T)(x)` is a `*T`, so `(*T)(p).M()` and bbolt's
`(*common.Page)(unsafe.Pointer(…)).Meta()` resolve through `T`'s method set.
The parser records how many `*` are written (`(**T)(x)`: two), and the value
has members only for exactly one `*` on a type that is not itself a pointer
type: `(*A)(x)` with `type A = *T` (also through an alias chain) or
`type P *T` is a `**T`, which has no methods, so nothing is followed. Other
undescribed callees are evaluated as the call they are (the failed-file
backstop already read them this way): `(<-fc)()`, `x.(F)()`.

**A call through a function declared per build variant has one answer only
when the variants cover every build of the caller and agree.** The first head
narrowed the variants to those that can be built with the calling file; the
review showed two wrong definite links that way: a `linux || darwin` caller
of `New().M()` with `New` only on Linux and Windows (the darwin build has no
`New`), and two Linux builds told apart by a tag named like a GOOS
(`-tags=freebsd` selects `//go:build linux && freebsd`, checked with Go,
`evidence/c-8/go-variant-configs.sh`). Now, with every name a free tag
(a GOOS or GOARCH name may be set as a tag), the call's variants must cover
every build of the calling file (no build without a declaration), and the
answer is taken from the variants that are the only declaration in some
build; when their results differ, the receiver's type is unknown (no
definite target; a call then gets the module's open name-only set). The
member is then selected by C-4's per-variant rule, as before. The test
for a build is a backtracking search over the constraint's names (bpf2go's
generated loaders name 15 tags), bounded by a step count, beyond which the
answer is unknown. This applies
only to several declarations of one name in one package; the values a
reassigned func local may hold are not build variants.

**The toolchain route names the type of a pointer conversion.** The opt-in
helper (`golinks.go`) recorded no declaration for a conversion whose type is
written `(*T)`, so it could neither confirm nor refute the new links. It now
unwraps the pointer, and on the toolchain fixture and on restic it confirms
the source-only target.

## Kept as it was

- Results of library types (standard library, dependencies), including
  methods promoted from an embedded library type: unresolved, as on `main`.
  The type facts stay where they were (`data.expr` keeps the full receiver
  description), so a later chunk can use them without a stored-format change.
- Interface-typed results: dispatch candidate sets.
- Type-parameter results: unresolved unless the constraint decides, as on
  `main`.
- Package-level names declared in several build variants (gin's `Form`,
  cilium's `testutils.RunWithToken`): candidate sets (item `go-generated`).

## Evidence

`evidence/c-8/README.md` (its first section is the final head's): every Go
link and symbol of all 20 Go pins compared with a build of `main` (+10,741
definite links, none lost or retargeted, no site added or removed, all
200,941 symbols kept); Go level 2 77.10% → 77.81% (scoreboard over SW-3),
79.11% → 79.65% in the plan's Go section; 20 newly definite links hand-checked
true; toolchain agreement on restic with 0 disagreements; three identical
cold indexes; user CPU time unchanged. The plan's generated block in this
branch is `main`'s: `main` merged C-9, whose Rust input was not archived, so
the block cannot be regenerated with it here.

## Not built

- Explicit generic instantiation (`As[*Fwd](x).M()`): needs type arguments
  and type-parameter positions stored at parse time (a module version bump);
  about 300 links across cilium, pebble and golang/tools.
- Inference of type arguments through an interface (fiber's
  `apptest.Ctx(t, New())`): the result is an interface anyway.
- A candidate set for a variant-declared function whose variants return
  different named types (unresolved now): it needs a type value that holds
  alternatives.
- C-4's selection over a type declared in several build variants keeps one
  GOOS per configuration, so a type split as `linux && !freebsd` /
  `linux && freebsd` is still selected definitely from a Linux file, although
  `-tags=freebsd` picks the other. Found while answering the review; C-4's
  rule, not changed here.
- `defer back()` where `back` is the closure a checkout helper returns
  (restic `rtest.Chdir`): function literals are not symbols.
