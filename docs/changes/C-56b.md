# C-56b: Go's implements pass as a plain value, and one id space for both builds

## Why

C-56 (keep Go's global index between runs of a session) needs something to keep that is a value: bounded, sized like C-55's kept inputs, frozen under the tests, and holding nothing that reaches into the resolver that made it. The C-56 note found that the implements pass's caches (`views`) hold closures over their resolver, so they cannot be kept.

Reading the pass again for this chunk showed that what C-56 needs to keep is not those caches but the pass's **decisions**:
- which interfaces have a complete implementer list;
- which types may implement which interfaces;
- which types do, with two flags (pointer receiver, and whether the method signatures are identical).

They are all by symbol id. The pass's other output, the `implements` links, can be rebuilt each run from the current symbols: their key and range carry the type's offsets.

The structure the pass reads (`index()`, 1.8 s of a cli/cli body edit's 3.1 s) is rebuilt every run in any sound scheme, so it is not part of this.

## The change

- **The implements pass returns a value.** `implementsDecisions()` makes every decision the pass made before, in the same order, and returns them as an `ImplementsDecisions`: lists of ids and flags, in the order made (type-major, as before). `applyImplements()` then fills the dispatch sets and adds the `implements` links for the run's scope, from the current symbols. Nothing reads the dispatch sets while the pass runs, only link resolution afterwards, so filling them after the pass changes no decision.
- **The value is plain data, shown in every test.** Under the test suite (`PYMTHEG_TEST`) the decisions cross JSON before they are applied, so every Go test runs on a value that can hold nothing but ids and flags.
- **One id space.** The notes pass (`linkNotes`, the analysis build of the index) now computes its symbols' ids under the store's project id, not its own (`go-overflow`). Its ids are then exactly the ids the store gives the same symbols. The test of C-56a now checks that equality, per file. Both builds of the index therefore name every declaration alike, and one kept value can serve both.

## What does not change

The decisions, the links, the notes and every stored row. Checked by indexing restic and cli/cli cold with main (54cd0e6f) and with this build, into stores with one project id, and comparing them row for row. Seeded edits through the MCP worker (35 each) all equal a cold index. Results are in [evidence/c-56b](../../evidence/c-56b/README.md).

## What C-56 does with it

It keeps the `ImplementsDecisions` of a run in the index session, under C-45's rules. The key is:
- every Go file's `surface.global`, which covers declarations, method sets, embeds and signatures;
- the context files, which hold the external and dependency facts;
- the toolchain facts;
- the module version.

A later run with the same key applies the kept decisions instead of making them, saving the pass's 992,496 type and interface pairs on cli/cli (about 0.65 s per build, two builds).
