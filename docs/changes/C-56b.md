# C-56b: Go's implements pass as a plain value, and one id space for both builds

## Why

C-56 (keep Go's global index between runs of a session) needs something to keep that is a value: bounded, sized like C-55's kept inputs, frozen under the tests, and holding nothing that reaches into the resolver that made it. The C-56 note found that the implements pass's caches (`views`) hold closures over their resolver, so they cannot be kept.

Reading the pass again for this chunk showed that what C-56 needs to keep is not those caches but the pass's **decisions**. The value records interfaces with a known, nonempty source-only method set, type/interface pairs that remain possible, and pairs that pass the source-only structural check. Each structural match carries a pointer-receiver flag and a signature-identity annotation of `identical`, `different`, or `unknown` (review: they are structural matches, not verified implementations; a pair whose signatures differ is listed, and its link is unresolved with `identity: "different"`).

They are all by symbol id. The pass's other output, the `implements` links, can be rebuilt each run from the current symbols: their key and range carry the type's offsets.

The structure the pass reads (`index()`, 1.8 s of a cli/cli body edit's 3.1 s) is rebuilt every run in any sound scheme, so it is not part of this.

## The change

- **The implements pass returns a value.** `implementsDecisions()` makes every decision the pass made before, in the same order, and returns them as an `ImplementsDecisions`: lists of ids and flags, in the order made (type-major, as before). `applyImplements()` then fills the dispatch sets and adds the `implements` links for the run's scope, from the current symbols. Nothing reads the dispatch sets while the pass runs, only link resolution afterwards, so filling them after the pass changes no decision.
- **The links of a scoped run.** A body edit of one implementer's file is resolved scoped to that file: its `implements` links are written again, and every other file's stay. A test with two implementers in two packages checks that both links remain and the store equals cold (review: skipping one in-scope link passed every test).
- **The value is plain data, shown in every test.** Under the test suite (`PYMTHEG_TEST`) the decisions cross JSON before they are applied, so every Go test runs on a value that can hold nothing but ids and flags.
- **One id space.** The notes pass (`linkNotes`, the analysis build of the index) now computes its symbols' ids under the store's project id, not its own (`go-overflow`). Its ids are then exactly the ids the store gives the same symbols. The test of C-56a checks, per file, that `notesSymbols` under the store's project id gives the stored ids. A test seam (`notesProbe`) receives the symbols each live notes pass names; a test indexes through `analyze` and checks that every one has the stored id for its file and key (review: with `analyze` passing the old project id, the notes-id tests passed). Both builds of the index therefore name every declaration alike.

## What does not change

The decisions, the links, the notes and every stored row. Checked by indexing restic and cli/cli cold with this chunk's first base (54cd0e6f, C-55 before its reviews) and with this chunk on it (b06e44de), into stores with one project id, and comparing them row for row. Seeded edits through the MCP worker (35 each) all equal a cold index. Results are in [evidence/c-56b](../../evidence/c-56b/README.md). The branch has since merged main (C-55, C-63, C-56a). On the pushed tree the suite is `npm test` 3,432 of 3,432 and `npm run test:backend` 97 of 97.

## What C-56 does with it

It keeps the `ImplementsDecisions` of a run in the index session, under C-45's rules. C-56 keys source-only implements decisions by the resolver mode, Go module version, context file paths and contents, and the complete Go file inventory keyed by path and parse state. The fingerprint covers package and import facts, build constraints, test membership, ordered declaration and embedding facts, and every type ID the value can name. It preserves the order of ordinary functions relative to other declarations. The C-45 session scope supplies the project and store identity and index settings. The normal notes and storage passes can share a value when these inputs agree. The resolver that ignores lossy packages uses a separate value. Toolchain-backed links are applied separately from the current toolchain facts.

(Review: the key first proposed here, each file's surfaces, missed four cases. A function added under another build constraint; the order of a function and a type alias of one name; a failed file, which has no surface, moving packages; and the decisions of the resolver that ignores lossy packages, which differ.)

The decisions name types by id, and a body edit can renumber a function-local type or an anonymous struct (C-56a: two `init` in one file). The key does not rely on ids being stable: it holds the ordered declarations and every type ID, so a renumbering misses it and the decisions are made again.

A later run with the same key applies the kept decisions instead of making them, saving the pass's 992,496 type and interface pairs on cli/cli (about 0.65 s per build, two builds).
