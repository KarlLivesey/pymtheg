# C-21: the Rust grammar accepts six valid shapes it rejected

Under the whole-file rule a Rust file the grammar rejects is failed entirely,
and links that could depend on it are withheld. C-15 found that 27 of the 29
failed files in the five repositories with failed Rust files are valid Rust
that the vendored grammar rejects. This chunk patches the grammar for those
six shapes. Across all 20 Rust sweep pins, turborepo's Rust workspace and the
pinned Vector corpus, 48 files are newly read (C-15 counted 27 placed in a
crate; the others are clap tests, swc and tauri files and one Vector test), and
every file that parsed before keeps exactly its tree.

## What changes for users

Valid Rust that used to fail whole files is read:

| Patch | Valid Rust it accepts                                                                                                                                      | Upstream                                |                  Newly read files on the pins |
| ----- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------- | --------------------------------------------: |
| 0009  | A macro named like a primitive type: `str![[r#"…"#]]` (snapbox snapshots), `u8!(…)`; and `str<…>` with generic arguments as a type path (proc-macro input) | issue #322 (open)                       |              31: clap 13, mdBook 17, dioxus 1 |
| 0010  | A lifetime first in `dyn` bounds: `dyn 'a + Display`, `dyn 'static + for<'a> FnMut(…)`                                                                     | none; PR #258 did `impl`                |               9: swc 6, turborepo 2, dioxus 1 |
| 0011  | Several attributes on a function parameter; attributes on closure parameters                                                                               | issue #276 (open)                       | 4: alacritty, tauri, turborepo, Vector 1 each |
| 0012  | `box` patterns (**nightly only**, `#![feature(box_patterns)]`)                                                                                             | issue #14, closed PR #83                |                                  2: turborepo |
| 0013  | `where dyn Trait: Bound`                                                                                                                                   | none found                              |                                     1: rustls |
| 0014  | A turbofish in a struct pattern: `let S::<T> { .. } = p;`                                                                                                  | PR #301 (open; its struct-pattern line) |                                     1: dioxus |

Each patch is its own file in `grammars/rust/patches/` with a header naming
the Rust reference section and the upstream issue or pull request, and its own
`test/corpus` cases, which run with upstream's in the build. All six are ours
(`"origin": "pymtheg"` in the manifest); no upstream pull request exists for
any of them except #301, of which only the struct-pattern line is taken (its
attribute change overlaps PR #319, already patch 0001).

`box` patterns are nightly-only Rust. The grammar accepts them because real
crates built on nightly write them (turborepo). `box` is a reserved keyword
in every edition, so no valid program binds a name `box`, and keyword
extraction only makes `box` a keyword where a pattern may start.

## Tree shapes and the Rust module

New node shapes, and how the module reads each:

- **0009** `macro_invocation(macro: identifier "str")`: the same shape as any
  macro named by an identifier, so `str!` is an ordinary macro invocation
  (looked up in the macro namespace; tested against a local `macro_rules! str`).
  `generic_type(type: primitive_type, …)`: the module reads the type's text
  like any generic type; nothing in it names a primitive specially.
- **0010** `dynamic_type(trait: bounded_type(lifetime, trait))`: the module
  reads types inside a `dyn` generically, so the trait is still referenced
  (tested: `dyn 'a + Code` links to `trait Code`).
- **0011** several `attribute_item` children before a parameter in
  `parameters`, and `attribute_item` children in `closure_parameters`. The
  module already collected stacked attributes for a parameter (cfg, arity).
  **One change was needed:** closure parameter bindings were read from every
  named child of `closure_parameters`, so the identifiers inside
  `#[allow(unused_variables)]` became closure-local bindings and would have
  shadowed a function `unused_variables()` in the body (a wrong definite link
  to the local). `patternNames` now ignores attribute items
  (`src/graph/languages/rust/parse.ts`); the test fails without it.
- **0012** `box_pattern(inner pattern)`: bindings are collected through the
  inner pattern, and names inside it are classified as pattern references
  like any other `*_pattern` (tested: `box message` binds `message`; the
  variants inside `box` link as patterns).
- **0013** `where_predicate(left: dynamic_type)`: the left type's trait is
  referenced as in any other position.
- **0014** `struct_pattern(type: generic_type(type_identifier, type_arguments))`:
  the module already climbs from a `generic_type`'s head to the pattern
  (shared with tuple-struct patterns), so the struct is linked as a pattern
  constructor and the fields bind.

The Rust module version moves to 39 (main is at 38 after C-18), so
stored graphs re-index and failed files are parsed again.

## Build

`node grammars/build.mjs rust --write` on the dev server (tree-sitter CLI
0.27.2, wasi-sdk 34.0, binaryen version_132; upstream `tree-sitter test`
passes with the new corpus cases), then the verify run: both builds gave
sha256 `421c975a…` (`evidence/c-21/build-verify.txt`). Each of the six
patches also builds and passes the corpus on its own over 0001–0008.

## Tree gate (the established corpus rule)

Every `.rs` file of the 20 Rust sweep pins, turborepo and the pinned Vector
corpus, parsed with main's grammar and this one, compared node by node (type,
field, named, byte range; [evidence](../../evidence/c-21/tree-gate.md)):

1. **11,022 of 11,022 files that parsed before give identical trees.**
2. **48 files are newly read**; six single-patch builds tie each to exactly
   one patch (0009: 31, 0010: 9, 0011: 4, 0012: 2, 0013: 1, 0014: 1).
3. **No file that parsed before now fails.** Each single-patch build also
   keeps every tree and breaks nothing.
4. **19 files still fail**, each with its cause: 10 that are not Rust (2 mdBook
   documentation snippets, 8 tauri handlebars templates) and 9 valid shapes
   listed under "Remaining gaps".

## Tests

`test/graph-rust-grammar.test.mjs` indexes one fixture per patch through the
public graph answers: in each, a file that used to fail now gives its symbols
and a call inside it links (`check` → `expected`, `boxed`, `depth_of`,
`report`, `choose`, `describe`), and the shape's own references resolve
(`str!` → `macro_rules! str`, `dyn 'a + Code` → `trait Code`, the struct
behind a turbofish pattern, the variants inside `box`). Negative cases: the
attribute on a closure parameter binds nothing (`unused_variables()` reaches
the function), and `box message` binds a local so `message.len()` does not
reach the function `message`. Four W2-V fixtures that recorded these gaps as
"still rejected" moved to `fixed/` and now carry these assertions. A
tree-identity test parses the nine ordinary fixtures in
`test/fixtures/rust-grammar/` (the W2-V fixtures and a new `ordinary/adjacent.rs`
with the shapes next to each patch: `dyn T + 'a`, `impl 'a + T`, one parameter
attribute, plain closures, tuple-struct turbofish, where clauses, casts before
`<=`) and compares every node with digests written by the previous grammar.
The rustc check now covers `ordinary/` and runs the nightly fixture with
`RUSTC_BOOTSTRAP=1`; all fixtures pass rustc 1.98.1.

## Remaining gaps

Still rejected (each fails its file honestly; fixtures in
`test/fixtures/rust-grammar/remaining/`): a numbered field in a struct
pattern (`HexColor { 0: x }`, 5 generated swc visitor files), an attribute on
a later tuple element (swc `config/mod.rs`), `()` on the left of a where
predicate (an embassy compile-fail UI test), `char::<_, E>(…)` and
`+ for<'a> B<'a>` bounds (Vector), and the other W2-V shapes. Not Rust: two
mdBook documentation snippets and eight tauri handlebars templates.
