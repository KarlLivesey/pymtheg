# C-60 A union callee's parts, keys of renamed files, and a non-object config base

Three faults on main (`b6fd7c9`), each found by an investigator with a
fixture, each fixed with a test that fails on main.

The TypeScript module version moves: keys of renamed JavaScript files
change (fault 2), so old stores re-index. The manager assigns the number at
merge.

## 1. A union callee took one part's signature for every part

**The fault.** The judge (W2-D) caches the signature a call takes by the
call node alone (`prepare` in `src/graph/languages/typescript/judge.ts`).
A union callee, such as `const selected = flag ? good : overloaded`, is
judged part by part on the same call node. So the second part was given the
first part's cached signature.

**The fixture.** It is strict, and `arg` comes from a failed file
(`export const arg = ;`). `good(x: string | number): Clean` and an
overloaded `overloaded(x: string): Clean; overloaded(x: number): Other`
are called as `selected(arg).run()`.

- On main, `flag ? good : overloaded` stored a definite link to
  `Clean.run`: `overloaded` reused `good`'s signature, whose return does
  not depend on the argument.
- `flag ? overloaded : good` stored `invalid-code`.

**The fix.** Each part is judged without the call's memo, and the joined
answer is the call's, cached by the outer `prepare` as before. Both orders
are now `invalid-code`. With the file repaired, the link is ambiguous
between `Clean.run` and `Other.run` in both orders.

**Tests** (`test/graph-typescript-resolution.test.mjs`):

- both orders, broken and repaired;
- every order of a three-part union callee (`good`, `overloaded`,
  `numeric`) gives the same link, broken and repaired.

Both fail on main: the first with a definite link where `invalid-code` is
expected, the second with two different answers across the six orders.

## 2. Hashed key parts of a renamed file depended on other files

**The fault.** A locally bound `require`, `module` or `exports` reaches the
compiler under a fresh same-length name (`rename.ts`). That name is chosen
so that no captured file contains it, so it depends on every captured
file's text. C-49 restores the names before keys are numbered. But the
hashed scope parts were hashed from the compiler's text, with the fresh
name in it. The parts are `[callback:…]`, `[block:…]`, `[case:…]`, and a
member's branch in `symbols.ts`.

**The fixture.** An AMD `define(function (require, exports, module) {…})`
and a CommonJS `outer(require)` with a callback. On main, changing an
unrelated file to contain `requirf` changed the `[callback:…]` keys of
both files' inner functions, and with them their identities and ids.

**The fix.** `scopeKey` hashes the restored text (`keyNames`) at all five
sites. C-49's note is corrected.

**Test** (`test/graph-typescript-keys.test.mjs`). After the unrelated edit,
every key, identity and id in the two files is unchanged, and the store
equals a cold index. With the raw text hashed (main), the keys differ.

## 3. A config base whose root is not an object

**The fault.** A `tsconfig.json` may extend a base that the compiler
cannot use because its root is not an object (`[]` or `55`: TS5092). The
compiler drops the base.

- Reached by relative path, the file fails.
- Reached by package name, the module took the base as read: it removed
  the `incomplete-config` marker, and the library link was stored.

**The fix.** 5092 joins the codes that keep the marker (6053 and 5083 for
an unreadable base, and syntax errors in the base).

**Test** (`test/graph-typescript-installed.test.mjs`). Both roots, by
package name and by relative path. By package name, the link is
`incomplete-config`; by relative path, the file fails. On main, the
package case stores the library link.
