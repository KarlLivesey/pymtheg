# C-60 A union callee's parts, keys of renamed files, and a non-object config base

Three faults on main (`b6fd7c9`), each found by an investigator with a
fixture, each fixed with a test that fails on main.

The TypeScript module version moves from 49 to 50 (assigned by the
manager): keys of renamed JavaScript files change (fault 2), so a store
written by an earlier version is rebuilt, never reused with its old keys.

## 1. A union callee took one part's signature for every part

**The fault.** The judge (W2-D) caches the signature a call takes by the
call node alone (`prepare` in `src/graph/languages/typescript/judge.ts`).
A union callee, such as `const selected = flag ? good : overloaded`, is
judged part by part on the same call node. So the second part was given the
first part's cached signature.

**The fixture.** It is strict, and `arg` comes from a failed file
(`export const arg = ;`). `good(x: string | number): Clean` and an
overloaded `overloaded(x: string): Clean; overloaded(x: number): Other`
are called as `selected(arg).run()`.

- On main, `flag ? good : overloaded` stored a definite link to
  `Clean.run`: `overloaded` reused `good`'s signature, whose return does
  not depend on the argument.
- `flag ? overloaded : good` stored `invalid-code`.

**The fix.** Each part is judged without the call's memo, and the joined
answer is the call's, cached by the outer `prepare` as before. Both orders
are now `invalid-code`. With the file repaired, the link is ambiguous
between `Clean.run` and `Other.run` in both orders.

**Tests** (`test/graph-typescript-resolution.test.mjs`):

- both orders, broken and repaired;
- every order of a three-part union callee (`good`, `overloaded`,
  `numeric`) gives the same link, broken and repaired.

Both fail on main: the first with a definite link where `invalid-code` is
expected, the second with two different answers across the six orders.

## 2. Hashed key parts of a renamed file depended on other files

**The fault.** A locally bound `require`, `module` or `exports` reaches the
compiler under a fresh same-length name (`rename.ts`). That name is chosen
so that no captured file contains it, so it depends on every captured
file's text. C-49 restores the names before keys are numbered. But the
hashed scope parts were hashed from the compiler's text, with the fresh
name in it. The parts are `[callback:…]`, `[block:…]`, `[case:…]`, and a
member's branch in `symbols.ts`.

**The fixture.** An AMD `define(function (require, exports, module) {…})`
and a CommonJS `outer(require)` with a callback. On main, changing an
unrelated file to contain `requirf` changed the `[callback:…]` keys of
both files' inner functions, and with them their identities and ids.

**The fix.** `scopeKey` hashes the restored text (`keyNames`) at all five
sites. C-49's note is corrected.

**Test** (`test/graph-typescript-keys.test.mjs`). After the unrelated edit,
every key, identity and id in the two files is unchanged, and the store
equals a cold index. With the raw text hashed (main), the keys differ.

## 3. A config base whose root is not an object

**The fault.** A `tsconfig.json` may extend a base that the compiler
cannot use because its root is not an object (`[]` or `55`: TS5092). The
compiler drops the base.

- Reached by relative path, the file fails.
- Reached by package name, the module took the base as read: it removed
  the `incomplete-config` marker, and the library link was stored.

**The fix.** 5092 joins the codes that keep the marker (6053 and 5083 for
an unreadable base, and syntax errors in the base).

**Test** (`test/graph-typescript-installed.test.mjs`). Both roots, by
package name and by relative path. By package name, the link is
`incomplete-config`; by relative path, the file fails. On main, the
package case stores the library link.

## Review (round 1)

**Keys of multi-line text (fault 2, continued).** The first version
restored the names in the serialised parts. Serialised, a name that follows
a line break is preceded by `\n` (`enabled &&\nrequire`), and the restore
did not see it, so such keys still moved. Each text part is now restored
before it is serialised. The tests in `test/graph-typescript-keys.test.mjs`:

- a multi-line condition beside a bound `require` for every hashed part
  kind (a block, a callback, a case, a conditional member and a logical
  member);
- twelve generated scope texts with the bound names beside escapes, quotes,
  a template and unicode, with a seeded generator.

**Callback parameters under a union callee (fault 1, continued).** A
callback's parameter takes its type from the signature its call chose
(`parameterTypeAt`). For a union callee the call's memo holds the joined
return, and that stood in for the parameter's type. The effect, also on
main:

- **A wrong definite link.** Both branches' callbacks take `Input` from a
  failed file, so `pick(value).run()` gave a definite `Clean.run`. The
  truth, once the file is repaired, is `Other.run`.
- **A lost link.** On the first version of this change, a member
  independent of the failed part, `value.clean.run()`, became invalid code.

Now each branch's own signature gives the parameter its type, and the
branches' answers are joined by the rule the return uses:

- all branches agree on a clean answer: that answer;
- any branch's answer failed for that parameter: invalid code;
- never one branch's answer for all.

Tests: both cases with two and three branches, in every order.

**An explanation that does not depend on branch order.** Of several failed
branches, the one whose reason sorts first in code-point order gives the
stored explanation (`cause.via`); before, the first branch's did. Test:
`flag ? identity : overloaded` with a failed argument stores one
explanation in both orders.

**The version.** Test: a store whose TypeScript rows carry version 49, with
one symbol row as main's keys made it, is rebuilt and equals a cold index.

## Measurements

The 19 installed TypeScript pins (C-42's `pins.json`) were swept with
main `b6fd7c9` and this branch, one after the other, in one session. Every
symbol (by file, kind, identity and key) and every link site (resolution,
target and checkout candidates by symbol key, library rows and data) was
compared, along with the stored row counts.

- **Eighteen pins are identical.**
- **vercel/turborepo differs only by fault 2's fix.** 251 symbols have
  different keys, and with them 144 links whose targets name those keys
  and 95 link sites keyed by them. All of them are in three files that
  bind `require`, `module` or `exports` as a parameter: webpack-wrapper
  fixtures under `crates/turborepo-trace-testkit/fixtures/js/nft/`. Those
  files are renamed for the compiler, and their `[callback:…]` keys
  differed only in the fresh name hashed into them. Symbol, link and
  library row counts are equal, and Level 2 is unchanged.
- **The investigator expected no key changes on the pins.** These are
  the only ones, and they are the restored-name keys fault 2 asks for: on
  main they would change again with any edit that changes the fresh name.
- colinhacks/zod's install was unavailable in the first head sweep; swept
  again on its own, it is identical too.

No link resolution changed on any pin: fault 1 and fault 3 change nothing
on these pins.
