# C-47b Expanding generic types are judged, not bounded

C-47 bounded the structural judgement and memoised it per program. One
shape still ran to the depth bound: a generic type that binds a larger value
at every level. Vitest's builder is the case. `TestAPI.extend` returns
`TestAPI<AddBuilderWorker<ExtraContext, K, T>>`, whose `ExtraContext` nests
the previous context in a new literal. The second reviewer found it with
`packages/vitest/src/node/types/config.ts` broken: the link
`(expression).reduce` in `test/e2e/test/scoped-fixtures.test.ts` reached the
depth bound (101 levels, 5,248 steps), and a larger budget changed nothing.

It is a genuine expansion, not a cycle the key misses. Each level's
judgement of the literal at `runner/types.ts:729` has a new binding for
`ExtraContext`, so its key is new; the cycle check, which ends repeats of a
key, never fires. Union keys already list each part once, which ends
expansions that only repeat parts (`A & B & B`), but not this one.

The TypeScript module version moves from 48 to 51 (provisional; 49 and 50
are taken by other open pull requests, and the manager assigns the final
number at merge). Rows change: the one Vitest link above.

## The cut

`tainted()` in `judge.ts` keeps, beside its stack of checks in progress, the
literal and function declarations being checked (`anchors`, keyed by the
literal's node or the function's declarations). When a check of a literal or
function starts while a check of the same declaration is in progress, it
does not judge the declaration's member types again (`expandedParts`):

- it checks the taint of each bound value the declaration's type nodes name
  (`relevant`, the same set its key holds), and of `self`;
- it records a cycle on the first check (a "not tainted" hit at its index),
  so its answer is provisional under C-47's rule until that check's group
  finishes.

## Why the cut is exact

The claim is that the second check loses no failure. Write a literal or
function judgement as its declaration D, its environment E (bound values by
type parameter) and `self` S. Its taint is decided by `taintedParts`: for a
literal, the taint of `type(t, E, S)` for each declared type node `t` of its
members; for a function, the same over its declarations' type nodes. So
the question is where `type(t, E, S)` reads E and S.

1. **The judge reads E only through names.** A type parameter's value is
   read only in `typeParameter`, by the symbol a node names
   (`context.env.get(symbol)`); `mentionsTypeParameter` asks only whether a
   named symbol is bound. A recursive alias reference reads only its own
   type arguments (C-47: "a recursive alias reference is judged by its own
   type arguments"); before that change it read every binding, and this
   argument would not hold. Every other handler reads the node, the
   program and the checker. So `type(t, E, S)` depends on E only through
   the values of the parameters `t` names, and on S only through `this`.
   The names are found by `parametersNamed`, which answers "all bindings"
   when a name in `t` is declared inside a function or class, whose
   parameters it could then read; the cut then checks every binding.
2. **Taint is an "or" over parts.** `taintedParts` is true when any part is
   tainted: a failed leaf, an object's member set or bound values, a
   union's or tuple's parts, a literal's or function's member types. Bound
   values enter a judgement only as parts (an object's binding, a value
   returned by `typeParameter`), never through a test that could turn a
   tainted part into a clean result. A type-level computation fails when a
   tainted input is among its children, and is otherwise clean or the
   checker's own type.
3. **So the taint splits.** From 1 and 2, by induction on the judgement's
   construction, the taint of a literal or function judged at (D, E, S) is
   `local(D) or tainted(E[P]) for some P named by D, or tainted(S)` where
   `local(D)` is everything decided by D's own nodes and the program alone:
   seed bindings, failed modules, unread names, member sets, unhandled kinds,
   failed checker lookups. `local(D)` is the same at every level of an
   expansion, because it does not read E.
4. **The first check decides `local(D)`.** The second check returns the
   other two terms, and records a cycle on the first. Under C-47's rule its
   answer is provisional until the first check's group finishes. If the
   group's answer is "tainted", the provisional "not tainted" answers are
   dropped, not memoised. If it is "not tainted", `local(D)` was false, so
   the second check's answer equals its full answer. Either way no
   memoised answer misses a failure.

The cut does not hide nested arguments: in `Box<Box<Bad>>` the inner `Box`
is a second check of `Box`'s declaration, and its binding `Bad` is one of
the values it checks.

Provisional "failed" answers of values judged in progress are unchanged:
C-47's rule already covers them, with its one known order dependence.
