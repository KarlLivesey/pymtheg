# C-9 Rust library paths

Rust records a library target when scoped lookup proves which outside crate
and symbol a written path names. This covers imports, calls, type references,
trait bounds and implementations, and macro paths. For example,
`use std::collections::HashMap;` records `std` and `collections::HashMap`.
`HashMap::new()` can record `collections::HashMap::new` when the declaring
member is known. `serde::Serialize` records the trait path, and a proven
`#[derive(Serialize)]` from the same dependency records `#[derive(Serialize)]`.

`import-path` covers an import of the whole crate. `qualified-path` covers a
written qualified symbol, including the symbol named in a `use` declaration.
`import-binding` covers a reference that follows a visible import. A prelude
name uses `declared-builtin` once the crate edition and scoped lookup prove
its implicit binding. An explicitly selected `<T as Trait>::member` uses
`explicit-trait`. The graph keeps the spelling of the named export through a
library re-export, so `tokio::sync::Mutex` stays `tokio` and `sync::Mutex`.
Dependency sources and receiver-type method selection are outside this change.

A macro import uses the same symbol as an invocation once its namespace is
proven. Function-like macros use `path!`, derives use `#[derive(path)]` and
attribute macros use `#[path]`. For example, `use core::arch::asm;` records
`arch::asm!` and `use thiserror::Error as Query;` records `#[derive(Error)]`.
An import with an unknown namespace or simultaneous macro and non-macro
bindings stays unresolved at the import site. A reference can still prove its
own binding through its syntactic namespace and the scope facts.
Serde's `extern crate syn; use syn::parse_macro_input;` preserves the
whole-crate alias proof while checking the export's macro namespace.
[Syn 3 public macro declaration](https://docs.rs/syn/3.0.0/syn/macro.parse_macro_input.html)

The unit of a Cargo dependency is its manifest package name, with the
manifest's hyphens preserved. A proven lockfile edge or an exact requirement
can supply `version` and `versionSource`. Paths into captured dependencies
use checkout symbol resolution, including crates in captured Cargo directory
source replacements. Cargo identifies registry sources by their index URL
and Git sources by repository URL and branch, tag, or revision. The lockfile's
owning dependency edge selects the package and version from that source.
Git directory replacements require a locked commit. If an applicable
replacement cannot be matched to one captured crate, the reference stays
unresolved. Cargo patch and replace entries affect only their packages and
checks that depend on their source identity.

An explicit `use` with a proven namespace can survive a derive, attribute or
function-like macro in that same module when the import and the path it
binds are otherwise proven. Rust rejects a generated item that conflicts
with that import in the same namespace. The rule leaves shadowing checks in
place for globs, prelude names, `#[macro_use]`, and macros in nested function
blocks. [Compiler evidence](../../evidence/c-9/README.md#checks)

The source-only associated-call check uses documented standard-library
owners and explicit trait paths. Locally declared type aliases supply a type
binding, so the resolver withholds library member credit when the alias alone
would supply the owner. Path dependencies with uncaptured manifests still need
checkout-boundary proof.

An existing type reference to `serde_test::Token` names `Token` and earns
Level 2. A separate call site written `Token::Str(...)` requires proof of
the associated declaration. When only the whole member site exists and its
owner is unknown, it stays unresolved. `qualified-path` promises the symbol
that the site names, so storing the qualifier `Token` at that call would
identify the wrong symbol. The graph adds no type site to score those calls.

The Rust module version moves from 28 on main to 31 so older stores re-index. Derived
and attribute macro references add written source sites. This change adds no
symbols. Coverage uses the stored library decisions on rebuilt Rust graphs.

## Serde review

The first PR head lowered Serde's all-sites Level 2 from 36.47% to 17.15%.
The review found 5,655 sites that main's coverage reconstruction credited
and that the first PR head withheld. All 30 sampled names matched the
source and public exports. The blockers overlapped across sites. The
review counted approximately 4,860 with an opaque derive or attribute in
scope, 2,400 with a multi-segment library value path, 400 with an unverified
namespace binding, and 260 with opaque module layout such as `#[macro_use]
mod` or `automod::dir!`. The explicit-import rule addresses the first group
only where a module binding and its namespace are otherwise proven. It
recovers 468 Serde links, and the final Serde all-sites Level 2 is 19.00%.
