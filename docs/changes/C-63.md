# C-63: Go calls through a local func value

## The ruling

For all three languages:
- **One local closure.** A call through a binding defined in the same function and provably assigned exactly one closure or func literal counts as resolved, inside the enclosing function. This is Rust's form: the link targets the enclosing function, with the binding's name and declaration span in `data.localBinding`.
- **A parameter.** A call through a parameter is unresolved, with the reason `local`, and is counted.

Before this chunk Go stored both shapes unresolved with no reason.

## What Go records now

Go's extractor already follows each local binding: its declared value, every later write, and any write it cannot see (an address taken, an op-assignment, a range or receive `=`). It now also records, per binding, its declaring identifier, whether it is a parameter, a named result or a receiver, whether it was declared with a value, and which values are func literals. A call through a local name is decided once the whole file has been read, so every write is known:

- **`localBinding`.** The binding is declared with a func literal and never written, or declared without a value and written exactly once, with a func literal. The second form is the recursive closure pattern, `var visit func(n *Node); visit = func(n *Node) { … visit(c) … }`. No write is hidden, the binding is not of a named type, and the call is inside a function or method. A binding of a named func type (`var h HF = func() {}`) is never claimed: a method of `HF` with a pointer receiver writes it through the implicit `&h` of `h.Reset()`, which the extractor does not see (review). The link targets that function or method, a definite Level 2 target, and records `data.localBinding` (name, start, end).
- **`local`.** The binding is a parameter, a named result or a receiver: the value comes from the caller. The parse fact is `data.localParameter` (name, start, end). If the resolver finds no target, the analysis records `data.reason` `local` (counted as `analyze.go.localParameterCalls`). On the pins none of these calls had a target before.
- **Everything else is as before.**
  - A local written more than once, or with a write the extractor cannot see, gets no target and no new reason.
  - A local assigned a named function (`h := Closure`) still resolves to that function, as it already did.
  - A closure inside a package-level func literal has no enclosing function and is as before.

Both facts are part of the parse result, so the Go module's version is now 33: stores indexed by 32 are re-indexed.

## Limits

- **A parameter name re-declared by `:=`.** `f, err := func() {…}, e()` in a function whose parameter is `f`: Go reuses the parameter (the body shares the parameters' scope), but the extractor makes a new binding in the body's block. The call `f()` is then claimed as the literal's. That is right unless a closure earlier in the body wrote `f`, which the new binding does not see.

## Checks

- **Tests.** `test/graph-go-local-calls.test.mjs` checks each shape, with the target and data it gets. Every shape that must not be claimed asserts main's target.
  - **Claimed:** one literal; the recursive form; a call from a closure in the same function.
  - **Not claimed:**
    - two literals;
    - an address taken;
    - a range or a receive `=` after the literal;
    - written once with a named function (`f = Closure`), or with one value of a multi-value call (`_, c = mk()`);
    - declared with a named function (`var f = Other`, `var g func() int = Other`);
    - a binding of a named func type, with a value or written once.
  - **`local`:** a parameter; a named result; a receiver.
  - **As before:** a named function value; shadowing; a package-level literal, and a closure inside one or inside a package-level `var` initializer.
  - **Version 32.** A third test rewrites a store's Go records as version 32 left them (version, and no local-call facts) and puts its completion record back, so the next run trusts everything but the version. That run parses every Go record again and equals a cold index.
  - **Mutations.** Each rule, broken in a scratch build, fails a test (review):

    | Broken | Fails |
    |---|---|
    | any single write counted, literal or not | the shapes test |
    | every `=` write taken as a literal | the shapes test |
    | any `var x = …` value taken as a literal | the shapes test |
    | an address taken not counted as a hidden write | the shapes test |
    | a range or receive `=` not counted as a hidden write | the shapes test |
    | a binding of a named func type claimed | the shapes test |
    | the module version left at 32 | the version-32 test |
  - **Edits.** A second test re-indexes edits that move a call between the cases, and each store equals a cold index. `test/graph-go-resolution.test.mjs` had pinned the old result for `helper := func() {}; helper()`; it now expects the enclosing function. The test's point, that the local shadows the package's `helper`, still holds.

- **Audit.** 60 of the new definite links, drawn with a fixed seed from all 8,577 (`evidence/c-63/audit-sample.txt`), were read against their source, from the binding's declaration to the call. All 60 are right. In each, the binding is declared once with a func literal (or declared without a value and assigned one literal once, the recursive form), and the call is inside the function the link targets, often from a nested closure such as a `t.Run` callback. No definite link in the sample is wrong. The final run (with named func types not claimed, which removed one link on pebble) was drawn again; the 60 were read again where the draw changed.

Two problems were found by the comparison, not the sample, and fixed before the final run:
- **Package-level func literals.** Closures inside a package-level func literal (2 in golang/tools' testdata) were marked `localBinding` with no target to give them.
- **Package-level var initializers.** So were closures in a package-level `var` initializer: protobuf-go's `LegacyFieldOrder = func(…) { inOneof := …; inOneof(…) }`, 6 links.

`localBinding` is now recorded only when the call's owner is a function or method, and the tests have both shapes.
- **Suite.** Build, type check and format check pass; `npm test` 3,408 of 3,408; `npm run test:backend` 97 of 97.
