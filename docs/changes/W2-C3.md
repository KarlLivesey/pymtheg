# W2-C3 — Rust ecosystem and cross-crate macro recall

Rust module version 24. This extends the source-only fallback; macro expansion is not executed.

## Scope-neutral statement macros

In `no_std` crates the standard exemption is limited to rustc-verified core macros: `assert`, `assert_eq`, `assert_ne`, `debug_assert`, `debug_assert_eq`, `debug_assert_ne`, `panic`, `todo`, `unreachable`, `unimplemented`, `matches`, `write`, `writeln`. `print`, `println`, `eprint`, `eprintln`, `vec`, `format`, and `dbg` require visible sysroot availability. Root `extern crate std` enables qualified std paths; its macro-use form enables bare names. Root `extern crate alloc` enables qualified alloc paths; its macro-use form enables bare vec/format. Competing captured bindings defeat the exemption. E4 continues to assume unseen code does not replace the standard names.

[Source audit](../../evidence/w2-c3/macro-source-audit.md) records inspected local registry definitions, hashes, and expansion reasoning. Generated declarations remain inside expansion blocks/branches; return-only arms do not introduce enclosing bindings. Tokio select's generated module, futures and handler patterns are inside its terminal block.

The invocation must have proven package provenance through a qualified dependency path, explicit import (including alias), or root macro-use extern crate. A package renamed *to* tracing/log/etc does not qualify; genuine dependency aliases do. Captured local modules, textual macros, competing imports and unproved glob suppliers defeat proof. Conditional dependency edges must be implied at the call site. No-implicit-prelude disables implicit macro-use fallback, while explicit macro imports remain usable.

Cargo.lock is now an analysis context file. The captured lock must uniquely select the audited crates.io release through the owning package's dependency list. Without a lock, only a literal exact `=x.y.z` requirement establishes the release. Path/git/custom-registry dependencies, patch alternatives, malformed locks and unsupported version requirements do not establish this contract.

## Captured workspace exports

Qualified dependency macro paths, explicit imports/aliases and root macro-use extern crates can resolve to captured workspace macro_rules definitions with effective macro_export. Textual and explicit scope precedence remains in force; later macro-use imports win. Unknown export sets stay unresolved. Foreign feature conditions cannot be proved merely by a same-named caller feature. Failed exports do not create invalid-code causes.

## Known limits

- Only the exact audited ecosystem releases qualify; other releases and unsupported Cargo version syntax remain conservative.
- Ecosystem glob/re-export provenance beyond proved empty globs is conservative. Unseen textual entries may replace logging macros; E4 was not extended to ecosystem macros.
- Arbitrary project macro body purity is not inferred. Procedural macros and generated bindings are not expanded.
- Sysroot aliases and other import routes beyond the tested availability forms can lose links.
- Existing grammar gaps, unverified module layouts and source-only namespace uncertainty remain. Uncaptured cross-crate macro definitions cannot become graph targets.
- E4 assumes unseen code does not replace the standard names; a failed macro-use file defining println that emits enclosing items is a known limit inherited from W2-C2.
