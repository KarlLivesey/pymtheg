# C-7 TypeScript member links and type parameters

Literal member calls use the checker's receiver type at the use site, including
when an optional chain short-circuits before an element access. The graph can
resolve named members on checkout objects held by a variable or returned from
a function. The checker can also identify a member reached through `await`.
When it supplies several distinct declarations, the graph keeps the candidate
set. A union can have a named member on one arm and an open index on another.
That call stays unresolved with `index-signature`. Direct lookups through
`any` and `unknown` now give receiver-specific reasons.

New object member symbols are anchored to their owning declaration and the
member path. They follow named top-level declarations in search. A shorthand
that passes a proven scoped function can link to the property declaration.
Existing links through shorthand to a named function still identify that
function. Type-literal members can anchor existing value references. Calls use
the existing declaration rule, including for declaration-only members.

The graph uses the same representation as existing plain local references for
type parameters. The link identifies the nearest enclosing symbol and records
the binding's name and declaration span in `data.localBinding`. The span
distinguishes parameters in overloaded or nested signatures. Queries already
have the enclosing declaration and the exact binding location, so there are
no extra type-parameter symbols or new source-link sites.

The review fix checks the source of the receiver before accepting a new
object-literal target. The TypeScript checker can merge two returned
objects with identical types and keep one member declaration. The graph
follows visible returns, conditional expressions, and binding assignments
to recover the actual alternatives. It keeps candidate sets when every
producer has a declaration it can name. An opaque producer or a write that
prevents that proof leaves the new link unresolved. Calls that main already
linked through its existing literal-member anchors keep their original rule.
