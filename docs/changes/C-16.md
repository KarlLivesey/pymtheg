The graph attributes a bare test global to Vitest, Jest or Mocha when the
compiler program requests that framework's ambient types. A compiler
`types` entry, a triple-slash type reference or a supported side-effect
import in a program source file provides the request. An absent side-effect
import also needs a matching dependency route. A package redirect or a
custom type root needs captured declarations to establish the framework.
An import of `expect` from another package, a local `test`, and a
checkout `declare global` binding take precedence. Multiple providers of
the same name produce candidates, including when TypeScript's bare lookup
selects only one of two captured declarations. A known competing ambient
type request outside this framework inventory leaves shared names unresolved
with `competing-test-globals` and the competing request names. For example,
Cypress can supply `expect` through Chai and `describe` and `it` through Mocha.
Bun's `expect` is declared inside `bun:test`. Bun's root types, the
Playwright and AVA entries, and `node:test` add no competing bare test names.

The checker supplies the owner of a named member through a captured return
type or re-export. A member declared directly in a named object type or
`declare const` type literal uses that declaration's dotted path. Existing
calls through same-file immutable property aliases or a constant literal
selector on a named library object can use the checker-selected member.
A union with different
declaring owners keeps both candidates. A call through an intersection can
name a single member when only one constituent declares it.

An explicitly requested Node type environment can identify documented
global calls and constructors when the checker finds no competing binding.
For example, a program requesting Node types with an ES-only `lib` can
identify `new URL(…)` without a captured `@types/node`. When the checker
selects a web declaration, the existing program-wide Node overlap rule
still applies, including through the new member forms. A second runtime
such as Bun keeps absent globals open.

When the checker lacks a member declaration, an annotation that names a
type imported from a proven package can identify the unit at Level 1. A
named return annotation can provide the same evidence. For example, a
function returning an imported Playwright `Page` establishes its package
unit, while the `locator` declaration still needs Playwright's types.
Call results whose type exists only in a missing dependency declaration,
contextually typed callback values without those declarations, and explicit
`any` receivers can remain unresolved. `declaring-owner` always comes
from the member declaration. The documented Node console alternative uses
`declared-builtin` evidence.

## Known limits

- A serialised Playwright `page.evaluate` callback uses the declarations from its enclosing compiler program under C-11, and cross-runtime execution falls outside that model.
- Runtime replacement such as `mock.method(Math, "max", …)` is outside the model, so the link names the declared member.
- Direct calls such as `err.toString()` retain the compiler's inherited `Object.prototype` binding, which can differ from an override on the runtime receiver.
