## 1. Const assertions

`x as const` and `<const>x` parse as a type reference named `const`. The
module stored them as unresolved `references` links: 2,719 across 19 pins.
A const assertion is not a reference, so it now stores no link
(`ts.isConstTypeReference`). `as Point` and `satisfies Point` still link to
`Point`.

## 2. Configs extended by package name

Every package-name `extends` (`astro/tsconfigs/strict`,
`@turbo/tsconfig/library.json`, `@repo/typescript-config/nextjs.json`) was
marked "from an external package". The marker was cleared only when the
compiler read the config from an installed path. Two things kept it in
place:

- **Not captured.** The extended files lie in the checkout behind a
  workspace link (`packages/turbo-workspaces/node_modules/@turbo/tsconfig →
  ../../../tsconfig`, `examples/ssr/node_modules/astro → packages/astro`). Their
  names (`strict.json`, `library.json`) match no context pattern, so they
  were never captured.
- **Not counted.** A config the compiler read through `node_modules` that
  turned out to be a captured checkout file did not clear the marker.

The fix has two parts.

- **Capture.** JSON files directly in a directory whose name contains
  `tsconfig`, or in a `typescript-config` directory, are now captured
  (`**/*tsconfig*/*.json`, `**/typescript-config/*.json`).
- **Resolution.** A package-name `extends` that the compiler reads through
  `node_modules` clears the marker, whether the file is installed or a
  captured checkout file behind a workspace link. It still does so only
  when the compiler reports no unreadable extended config. An `extends` of a
  package that is absent keeps the marker and its `incomplete-config`
  reason.

This capture is a static pattern. Capturing exactly the file that any
`extends` chain names would need a second capture pass: the module would
resolve each chain over the inventory and ask the core to capture what it
names. That pass would have to stay consistent across full and incremental
indexing and context-change detection. It is listed as further work.

A base reached by package name whose JSON has a syntax error keeps the
marker. The compiler reports it (1005) and drops what it cannot parse,
exactly as for an unreadable base (6053 or 5083).

Turborepo gains 12,273 Level 2 links from read configs, Astro 368 and tRPC
15. A further 602 Turborepo library links now name their symbol under the
read configs. As the review predicted, some links behind the read configs
now stop at their next blocker, such as missing build output or

## 4. Library targets beside an unread file

C-13 withheld every installed library target in a program that contains a
failed file, because the unread text might declare something that changes
the checker's answer. The first version of this item kept a target when no
unread file spelled a name involved. Review showed that this is not enough.
A script's top-level declarations are global. A failed script that merges
into a global interface retypes a value without spelling any name at the
reference:

- `interface HTMLElementTagNameMap { "my-el": MyElement }` makes
  `document.createElement("my-el").focus()` bind `MyElement.focus`;
- `interface Document { createElement(tagName: "canvas"): OffscreenCanvas }`
  makes `c.getContext` bind `OffscreenCanvas.getContext`.

A module's declarations are its own. It reaches the global scope or another
module only through `declare global`, `declare module` or `export as
namespace`. The rule is therefore that the target is kept only when every
unread file in the program meets all four conditions:

1. **It is provably a module.** Either it is a non-declaration `.mts`,
   `.cts`, `.mjs` or `.cjs` file, or the compiler's parse of its text has a
   top-level `import` or `export` statement that ends before the first parse
   diagnostic. Any such statement makes the whole file a module, and error
   recovery after it cannot remove it. A file whose module syntax comes only
   after its error, or never, is treated as a script. That includes a
   `.d.ts` without module syntax.
2. **It spells none of the names involved:** the reference, its receiver
   chain, and the segments of the target's path.
3. **It has no `declare`, `global`, `namespace` or `module` token, no
   triple-slash reference, and no `\u` escape.** The escape rule makes
   escaped identifiers, which a word scan cannot read, moot.
4. **It imports only modules the program already loads.**

The existing taint checks still fail a binding that resolves into the unread
file, and a receiver whose type reaches it. A kept link carries no
`no-unseen-declarations` assumption, because that is the assumption the check
verified. Beside such files, a module link is also computed as in a clean
program. Before this fix, a dynamic `import("./App.css")` named Vite's
ambient `*.css` declaration, where the clean index names only the unit.

Not covered, and withheld as before:

- a failed script or `.d.ts` without module syntax before its error;
- a CommonJS file (`module.exports` spells `module`);
- any failed file that uses an escape or one of the tokens above.

Fixtures check both directions:

- **Kept:** a failed unrelated module, and a failed module that imports only
  a module the program already has, keep the target of the project without
  the failed file. This holds again through the bundler differential pass,
  and for the module link of a pattern ambient module.
- **Withheld:** the two review fixtures (a script `.d.ts` merging
  `HTMLElementTagNameMap`, and a script merging an overload into
  `Document`) withhold the target. So do:
  - a failed file that is a script spelling no name;
  - a module whose only `export` follows the error;
  - a module with an escape;
  - a failed file that augments the library, declares a clashing global,
    imports a package the program lacks, or has a triple-slash reference;
  - a receiver whose type comes from the failed file.

  The reviewer's 19 further shapes (window merges, global functions, JSDoc
  in JavaScript, re-exports, `baseUrl` and `paths` shims) all withhold or
  stay unresolved, and the unrelated control keeps its target.

Gains: Vitest 3,602. The first version kept 8,394 links: Vitest 3,871,
Vite 3,479, Puppeteer 677 and Astro 367. The provable-module rule gives up
4,792 of them, 57%. On Vite, Puppeteer and Astro, and for Vitest's other
