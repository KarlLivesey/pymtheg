## 1. Const assertions

`x as const` and `<const>x` parse as a type reference named `const`. The
module stored them as unresolved `references` links: 2,719 across 19 pins.
A const assertion is not a reference, so it now stores no link
(`ts.isConstTypeReference`). `as Point` and `satisfies Point` still link to
`Point`.

## 2. Configs extended by package name

Every package-name `extends` (`astro/tsconfigs/strict`,
`@turbo/tsconfig/library.json`, `@repo/typescript-config/nextjs.json`) was
marked "from an external package". The marker was cleared only when the
compiler read the config from an installed path. Two things kept it in
place:

- **Not captured.** The extended files lie in the checkout behind a
  workspace link (`packages/turbo-workspaces/node_modules/@turbo/tsconfig →
  ../../../tsconfig`, `examples/ssr/node_modules/astro → packages/astro`). Their
  names (`strict.json`, `library.json`) match no context pattern, so they
  were never captured.
- **Not counted.** A config the compiler read through `node_modules` that
  turned out to be a captured checkout file did not clear the marker.

The fix has two parts.

- **Capture.** JSON files directly in a directory whose name contains
  `tsconfig`, or in a `typescript-config` directory, are now captured
  (`**/*tsconfig*/*.json`, `**/typescript-config/*.json`).
- **Resolution.** A package-name `extends` that the compiler reads through
  `node_modules` clears the marker, whether the file is installed or a
  captured checkout file behind a workspace link. It still does so only
  when the compiler reports no unreadable extended config. An `extends` of a
  package that is absent keeps the marker and its `incomplete-config`
  reason.

This capture is a static pattern. Capturing exactly the file that any
`extends` chain names would need a second capture pass: the module would
resolve each chain over the inventory and ask the core to capture what it
names. That pass would have to stay consistent across full and incremental
indexing and context-change detection. It is listed as further work.

Turborepo gains 12,196 Level 2 links from read configs, Astro 368 and tRPC
15. A further 602 Turborepo library links now name their symbol under the
read configs. As the review predicted, some links behind the read configs
now stop at their next blocker, such as missing build output or
uninstalled packages.

## 4. Library targets beside an unread file

C-13 withheld every installed library target in a program that contains a
failed file, because the unread text might declare something that changes
the checker's answer. TypeScript binds, merges, shadows and augments by
name. An unread file can therefore change a library target only:

- by spelling one of the names involved (the reference, its receiver chain,
  or a segment of the target's path), or
- by adding declarations beyond its own names (a `declare`, `global`,
  `namespace` or `module` token, or a triple-slash reference), or
- by importing a module the program does not already load.

The target is now kept when none of these hold for any unread file, as read
from the raw text and the program's own module resolution. The existing
taint checks still fail a binding that resolves into the unread file, and a
receiver whose type reaches it. A kept link carries no
`no-unseen-declarations` assumption, because that is the assumption the
check verified. Otherwise the resolve stage would never credit it.

Fixtures check both directions:

- **Kept:** an unrelated failed file, and a failed file that imports only a
  module the program already has, keep the same target as the project
  without the failed file. This holds again when a free `require` sends the
  file through the bundler differential pass.
- **Withheld:** a failed file that augments the library, declares a clashing
  global, imports a package the program lacks, or has a triple-slash
  reference withholds the target. So does a receiver whose type comes from
  the failed file.

Gains: Vitest 3,871, Vite 3,479, Puppeteer 677, Astro 367.

## Links that changed or were lost

Every definite link on main was compared with the candidate on all 19 pins.
The same comparison is used for identities
([changes](../../evidence/c-39/changed-definite-installed.jsonl.gz),
[kinds](../../evidence/c-39/changed-kinds.json)).

- **3,096 renamed library links, same package.** Main named only the import
  binding, as spelled (`node:path:default`), because the target was withheld
  and the lexical fallback applied. The kept target names the declaration
  the checker proves (`node:path:path`). That is how the same imports are
  named in programs without an unread file: 2,862 of the 3,276 changed or
  lost links have the identical name and kind linked to the identical target
  outside such programs. The rest are one-off imports with no such twin.
- **59 now name the declaring package.** For example,
  `eslint/config`'s `defineConfig` is declared in `@eslint/config-helpers`
  (the C-23 ownership rule).
- **8 became candidate sets.** `node:timers` re-exports the global
  `setTimeout` and `clearInterval`, which both the DOM library and
  `@types/node` declare. Main's single target was the lexical fallback.
- **46 Astro `getCollection` links became `external-package`.** On main the
  example's config could not be read, so its files fell to the inferred
  project, which contains every ambient `astro:content` declaration in the
  checkout. With the example's own config read, the program, like `tsc`
  there, does not see those files. They reach a real Astro project only
  through the generated `.astro/types.d.ts`, which `astro sync` writes and
  the checkout lacks.
- **67 lost, and 35 symbol identities gone, in 9 Turborepo example files that
  now fail.** These are consequences of reading the real configs:
  - **Svelte examples.** `@repo/typescript-config/svelte.json`, now read,
    sets `allowJs`. The example configs therefore include their JavaScript
    files, and they also extend the generated `.svelte-kit/tsconfig.json`,
    which is missing. The existing rule fails every file of a broken config;
    on main these files fell to the inferred project.
  - **`with-nextjs-elysia/packages/contract`.** Under its real config,
    TypeScript 5.9.3 asserts (`Debug Failure. False expression: Invalid
    argument: prerelease`), and C-13 containment fails the five files.

  These are the only symbol keys that change. Every other symbol on all 19
  pins is unchanged ([removed](../../evidence/c-39/turborepo-removed.txt)).
  The 174 link sites removed with these files, and the 2,719 `as const`
  links, are the only sites that disappear. None is added.

## Checks

The new tests each fail on main and pass here:

- const assertions;
- the shared config behind a workspace link and through package
  `exports`;
- an unrelated unread file, including the bundler differential pass.

The negatives (an absent extended package; unread files that augment,
clash, import a package the program lacks, reference a library, or feed
the receiver) hold on both builds.

Existing tests that encoded C-13's wholesale withholding were updated:

- **The W2-D differential harness.** It indexes each fixture clean and with
  a broken file. It now also accepts a library link that is kept beside the
  broken file (`unreadChecked`), and it still asserts that the library
  identity equals the clean index's. All ten differential fixtures pass that
  identity assertion.
- **K3** keeps its purpose. Its broken file now spells `Math`, so
  `Math.floor` is still withheld and flagged.
- **`written imports can be independent of …`** now expects
  `Promise.resolve`. The broken file there spells neither name.
- **The conformance sample.** Its unread `src/broken.ts` no longer withholds
  `String(value)`, which is now the standard library target. The sample gains
  a call to a name no program declares, as the kit's unresolved-link
  control. Build, type check, format check, the
TypeScript graph tests, the sweep tests and the full `npm test` results are
in the pull request.
