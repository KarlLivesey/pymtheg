# C-47 A TypeScript analysis that never returned: the structural judgement is bounded

A C-22 seeded-edit run on oclif/core (seed 4242) reached a tree on which a
cold index by main never finished. It stayed in `graph analyze typescript:
0/196` at full CPU for more than 85 minutes. It ignored the `timeout`
command's SIGTERM and a plain `kill`; only SIGKILL stopped it. The tree is
the one after the run's 17th edit (step 16; the run's log had stopped
printing three steps earlier, which is why it was first reported as the
13th). The edits are ordinary: comments, blank lines, duplicated lines, and
a `void 0;` inside an object literal in `src/parser/index.ts`, which makes
that file fail to parse.

The TypeScript module version moved from 45 to 48 with the first merge.
The expanding-type cut (review 2, the second reviewer's acceptance cases)
came after that merge, in its own pull request. It changes stored results
(vitest's `(expression).reduce` is judged instead of stopping at the
bound), so it moves the version from 49 (C-49, merged in between) to 50. Old stores re-index.
The cut and why it is exact are in [C-47b](C-47b.md).

## Where the time went

The hanging run was profiled under V8's tick profiler, as in C-26. The time
is not in the compiler. It is in pymtheg's structural judgement
(`judge.ts`, the C-13 rule for a receiver that depends on a failed file):
`referenceType`, `fromType`, `UnionType` and `tainted`, with
`getSymbolAtLocation` called from the judge's own `symbolAt`. The broken
`src/parser/index.ts` re-exports oclif's parser interface types
(`ArgInput`, `FlagInput`, `OutputFlags`…). Every receiver whose type
mentions them is therefore judged structurally, over oclif's recursive
generic flag types.

On these types the judgement recurses without end. The judge's cycle check
should catch it; why it did not is traced below.

## Why it sometimes finished and sometimes did not

The same tree, copied and indexed again on the same server, finished in
54 s, 90 s, 207 s and 322 s, and twice ran past 900 s. The work is not a
function of the source. The cause is the stack:

- **The judge swallowed stack overflows.** Its `symbolAt` and `resolved`
  wrappers, and seven other `catch {}` blocks in `judge.ts`, caught every
  exception, a stack overflow included. They answered "no symbol" or "no
  declarations" and went on. Recursion without end therefore hit the stack
  limit, resumed in the next branch, hit it again, and so on. That is
  exponential work at the edge of the stack.
- **Where the stack runs out is not deterministic.** It depends on V8's
  frame sizes, which change as functions are optimised on background
  threads. A run in which the overflow landed outside such a `catch` was
  ended by `structural()`, which then also treated the receiver as clean.
  That is a second defect: an overflow was taken as an answer.

## The fix: deterministic bounds on one judgement

The structural judgement now has two bounds. Each is a count, never a clock.

- **Depth.** At most 100 nested judgements (`JUDGE_DEPTH`). Since review 2
  this counts every recursive path of the judgement (types, expressions,
  taint checks and keys); before, only types and expressions.
- **Steps.** At most 200,000 type, expression or checker-type judgements
  actually computed (`JUDGE_BUDGET`). A memoised answer costs nothing. The
  count depends only on the source and on the judgements made before it in
  the same program, which the module makes in a fixed order.
- **A stack overflow inside a judgement counts as the depth bound.** It is
  never swallowed: every `catch` in the judge lets the bound through (and,
  since review 2, every handler in the module that could meet one; see the
  inventory below).
- **A memoised judgement that a bound interrupts** is reset, so no later
  answer sees a false "depends on itself".

When either bound is reached, or the stack runs out, the receiver's
judgement fails. `structural()` then fails the link as it fails any other
receiver that depends on the failed file: `invalid-code`, the failed file as
the cause, and the reason "the structural judgement reached its bound
(judge-budget-exhausted)". There is one reason for every bound, so the
stored row does not depend on which one the engine reached first.

*Correction (review 2):* this note first said here that an overflow was no
longer taken as an answer, and that the depth bound kept the judgement below
the stack limit. Neither was true of that version: three handlers in
`extract.ts` still went on with a partial answer, and the depth count left
out the recursion through the taint check and its keys. Both are fixed in
[review 2](#review-2-one-judgement-per-program) below.

**Results on the hanging tree, with the bounds alone.** Four cold indexes,
run at once on copies of the tree, finished in 30–31 s. Their files,
symbols, links, candidates and library targets are identical row for row.
The only differences are the copies' `node_modules` context stamps. 60
links failed with the bound, all receivers whose types reach the broken
parser module. With the cycle fix below, none does.

## Why the cycle check missed it, and the fix

`tainted()` (does a judged type depend on a failed file?) cut cycles with a
set of the judgements already seen, compared by object identity. The
recursion never repeated an identity, for three reasons, each traced on the
hanging tree with an instrumented build:

1. **A new environment at every level.** `Arg`'s `parse: ArgParser<T, P>`
   has `opts: P & Arg<T, P>`, which returns to `Arg`. Each pass binds `T`
   and `P` in a new environment (`bind`), so the same literal under the
   same bindings was a new object each time: environments #1, #8, #15, …,
   #4890, until the stack ran out.
2. **Bound values are new objects too.** `defaultHelp?: ArgDefaultHelp<T>`
   leads to `context: DefaultContext<Arg<T, P>>`, which leads to
   `options: T` and back to `Arg`. Here `T` is bound to `Arg<T, P>`, and
   judging that reference makes a new literal (and a new union) each time.
3. **Type-level computations start a fresh check.** `OclifConfiguration['topics']`
   is a `Record<string, {…; subtopics?: OclifConfiguration['topics']}>`.
   Judging the indexed access and the mapped type calls `tainted()` anew
   for each type reference inside them, so an outer check's `seen` set never
   met the inner one.

**The fix.** `tainted()` now keys its cycle check by structure:

- the kind;
- the node or symbol (a literal's node, a function's first declaration, an
  object's symbol; since review 2, all of a function's declarations);
- `self`;
- each type parameter's bound value, compared by its own key.

A union or tuple is keyed by its parts, and a failed or opaque value by its
reason. The checks in progress are shared across nested `tainted()` calls.
Re-entering a check in progress is a cycle, and it answers "not tainted",
leaving the answer to the other parts of the outer check (the usual fixed
point for "does any part depend on a failed file").

The key includes the bindings, so the same type under different arguments
(`A<Clean> | A<Failed>`) is still checked for each argument. Keys end at the
original, non-recursive bindings, and a value whose key is already being
computed falls back to its identity, so computing a key always ends.

**Result on the hanging tree:** no link reaches the bound now (before: 60).

- **Three of five sample sites** have no target, `local` or `external`:
  `defaults.options`, `argEntries.findIndex` and `(expression).value`.
- **Two are failed with a judged reason:** `arg.name.toUpperCase` is
  "unhandled type member of a computation", and `a.id.localeCompare` is
  "no member id of the object literal".

None is definite, which matches main's withholding of library targets beside
a failed file. Each cold index takes 32–34 s, and three copies agree row for
row. The bounds stay as the backstop: a test runs the committed fixture with
a one-step budget and checks the bound reason.

## The dependence graphs no longer take an overflow as an answer

The dependence graphs behind `reaches` (the gate at any depth) and the
overload check (`signatureDependsOnFailed`) do not run the judgement. But
their `symbolAt` swallowed a stack overflow, answering "no symbol", which
can drop a dependency. And `reachedFrom` turned an overflow into "does not
reach": a clean answer from an overflow. Now:

- inside the judge, an overflow always propagates as the bound;
- `reachedFrom` and the overload check catch it and fail the link as
  `invalid-code`. The cause is every failed file of the program, because
  which one is unknown. The reason is the bound's.

A test places an injected overflow (the module's `checkerFault` hook) on each
lookup of `conf` in turn. The receiver's link is unresolved every time, never
clean. One placement lands in the structural judgement and gives the bound
reason.

*Correction (review 2):* "every failed file of the program" read only the
program's own source files, and a failed file is usually not one (the
compiler is not given it). The fallback then had no cause and the link went
on unfailed. It now also takes every failed file the program's bindings
reach (the taint walk's causes).

**Not covered:** a non-returning loop inside the compiler other than C-26's.

## Review 2: one judgement per program

Review found three faults in the first version, each shown on a real pin
with a central file broken (`const = ;` appended).

- **redux-toolkit never finished** (killed at 1,500 s on this branch and on
  main; 75 s clean). Thousands of judgements each redid the same work.
- **Overflows were still taken as answers** in three handlers of
  `extract.ts` (the reviewer's case: a `RangeError` on the 8th checker call
  on `k` turned `invalid-code` into `unresolved no-symbol` with no cause).
- **Excalidraw: 95 links stopped at the bound** through real V8 overflows
  at a counted depth of only 40, so the result depended on the stack size.

### Why the work repeated

Tracing redux-toolkit showed type-level computations (`ReturnType`,
`UnwrapPromise`, `Exclude` over `BaseQuery`) judged about 170,000 times
each. Two rules made almost nothing memoisable:

- **One global cycle counter.** Any self-dependence anywhere (an inferred
  type argument whose constraint names itself, an F-bounded parameter)
  marked every enclosing answer as "met a cycle", so none was memoised,
  even after the self-dependent value had finished.
- **Keys and the recursive-alias rule read every binding**, including the
  ones inherited from enclosing aliases, so a key often read the very
  binding being judged, which is a self-dependence by the first rule.

Review also found the cycle rule itself unsound (F1). A hit on a taint check
in progress returned "not tainted" without counting as a cycle, so a
provisional answer was memoised. In the reviewer's case, `x.a.v.go`
depended on `r1.v.go` being judged first.

### The rule now

Every judgement in progress has an index on one stack:

- a bound value;
- an expression;
- a type parameter's constraint;
- a key;
- a taint check.

Re-entering one is a cycle, answered provisionally: "depends on itself",
or "not tainted" in the taint check. An answer that consulted an entry in
progress is provisional until that entry finishes. As in Tarjan's
algorithm, the root of a strongly connected group settles the group's
cycles, and an answer is memoised only if everything it consulted began
after it.

- **A self-dependence costs one evaluation.** It is settled when its own
  entry finishes.
- **A memoised answer can depend on the order of evaluation in one known
  shape.** When one cycle contains both an expression re-entry, whose
  provisional answer is "failed", and a taint-check re-entry, whose
  provisional answer is "not tainted", whichever link enters the cycle
  first fixes the memoised answer for the whole group. A review built the
  case from `typeof` cycles through mapped types (2 of 180 generated
  projects with `typeof` cycles, none of 80 without, and none of the four
  real broken trees, which gave identical rows in forward, reversed and
  shuffled file order). The direction is safe: a provisional "failed" can
  only add failures, so the effect is a link failed that could have been
  judged clean, never a clean answer for a type that reaches a failed
  file.
- **In the taint check, "tainted" is final at once**, unless a value judged
  in progress was consulted.
- **"Not tainted" waits for its group.** One that consulted only taint
  checks in progress is final for the whole group when the group's root
  finishes not tainted.

What is memoised per program:

- **Taint checks**, by key.
- **Type-level computations**, by node, `self`, the aliases being
  expanded, and the bindings named.
- **Checker types**, one judgement per `ts.Type`.
- **Expressions and call preparations**, as before, now under the same
  rule.

**Keys.** A literal's or function's key holds only the bindings its
declared type nodes name. A node naming a declaration made inside a
function or class holds them all. A function is keyed by all its
declarations (F2: the first declaration alone let an overload subset share
a key). A key that consulted an entry begun before it is not cached (F2).
A union's key lists each part once. An expanding type builds
`A & B & B …` level by level (redux-toolkit's
`Api<…, Definitions & NewDefinitions>`), and without repeats the key
repeats and the cycle check ends it.

**A recursive alias reference is judged by its own type arguments.**
Before, the reference read every binding in scope, inherited ones included.
The alias's body names nothing else that varies, and the rest of the alias
is judged at its first expansion. This is the one change of rule. On
react-hook-form with `src/types/form.ts` broken it changes 17 links
against main. Four that main failed are no longer failed:
`field._f.onBlur` and `field._f.onChange` become `local`, and
`field.value.includes` and `field.value.push` become `external`. A review
followed `_f`'s type, which has two parts.
- **`RegisterOptions`.** It leads through `FieldPath`/`FieldPathValue` to
  `PathInternal`/`PathImpl`, and then to `Primitive`,
  `BrowserNativeObject`, `OpaqueType`, `IsEqual` and `IsTuple`. None of
  these names the broken file.
- **`ref: Ref`.** It does reach the broken file: `Ref` → `CustomElement`
  → `FieldName` → `IsFlatObject` → `NestedValue`.

`onBlur` and `onChange` are members of `RegisterOptions`, not of `ref`, so
their links depend only on the first part. Main's failure came from the
old rule reading inherited bindings, and this branch's rows are the right
ones. The other 13 are `invalid-code` on
both, with a different reason. Built with the old recursion rule, this
branch gives main's rows exactly, so the rule change accounts for all 17.

**Bounds.** The depth bound counts every recursive path of the judgement:
types, expressions, taint checks and keys. A deep judgement therefore ends
at the count, not at V8's stack. The checker's own recursion is not counted,
and an overflow inside it still counts as the depth bound. A program-wide
step budget, `JUDGE_PROGRAM_BUDGET` (8,000,000, like the taint walk's), is
the backstop, with the same reason. A test hook, `judgeProgramSteps`, sets
it. If the program budget does run out, which links end at the bound
depends on the order in which links are judged (it does not depend on
stack size); no tree measured comes near it (the whole judge spends under
20,000 steps on the oclif tree, and 13,327 in the largest single judgement
on redux-toolkit).

**Expanding types.** Some types bind a larger value at every level, so no
key ever repeats. vitest's builder is one: `TestAPI<AddBuilderWorker<ExtraContext, K, T>>`
nests the previous context in a new literal each time. The cut gives the
answer the judgement without it would give, where that one ends:

- **For one set of bound type parameters, a literal's or function's own
  failures belong to its declaration nodes,** whatever values are bound:
  seed bindings, failed modules and unhandled kinds. The values only
  decide what is reached through them.
- **So a second check of the same declaration with the same parameters
  bound**, while the first is in progress, checks only the bound values it
  names and `self`. It leaves the declaration's own parts to the first
  check, as a cycle on it.
- **Which parameters are bound is part of what "the same" means.** An
  unbound parameter is judged by its constraint, and the constraint is not
  one of the declaration's own nodes; `this` in a type literal with no
  `self` is the same literal with nothing bound. The first version of the
  cut compared the declaration alone, and so skipped such a constraint:
  with `type Builder<T extends Bad> = { get(): T; set(v: T): this; … }`
  and `Bad` from the failed file, `wrap({ v: b }).get().n.toFixed()` came
  out clean where the judgement without the cut fails it (a reviewer's
  case: 54 links over 620 generated projects, none on the real trees).
  With the bound parameters in the comparison the two agree on all 620, on
  vitest and on Excalidraw, and vitest's builder is still judged. Whether
  failing that link is itself more than is needed (a bound parameter's
  constraint does not change member lookup) is left open; this change
  keeps the rule main already has.
- **Nested arguments are still checked.** `Box<Box<Bad>>` still finds
  `Bad`: it is a bound value of the inner `Box`, and that value is checked.

**The second reviewer's key suspicions are all closed:**

- **The function key used only `decls[0]`.** It now uses every declaration.
- **A key computed while a binding was mid-evaluation was cached
  permanently.** It is now cached only if it consulted nothing begun before
  it.
- **A cut inside a nested `tainted()` could be memoised into a binding's
  cached value.** A bound value is now memoised only under the same rule, so
  a cut on a check outside the value leaves it unmemoised.

### Overflows are never answers

The three handlers now treat an overflow as unknown:

- the receiver's causes (`receiverCauses`);
- its names (`namesInReceiver`);
- its member set (in `structural`).

A gate that is unknown makes the receiver be judged. An unknown member set
fails the link as `invalid-code`, with every failed file as the cause and
the bound as the reason. `aliasChain` and the contextual-type lookup in
`taint.ts` swallowed every exception, which shortens the chain and can drop
a seed. They now let a `RangeError` through to the caller's own rule.

## Why the run ignored SIGTERM

The CLI handles SIGINT and SIGTERM by aborting an `AbortController`
(`src/cli/main.ts`). The graph command checks that signal only at its
`await` points, between modules and stages. A language module's analysis
is one synchronous call on the main thread, so while it runs the event loop
never turns, and the handler never runs. The signal is received but not
acted on, and the process continues until SIGKILL. `timeout` sends
SIGTERM, so it was ignored too.

AGENTS.md's CPU-cancellation contract (the production coordinator, with a
worker that cannot finish naturally) is honoured by `check`: its analysis
runs in a `worker_threads` worker (`analyseInWorker`,
`src/cli/coordinator.ts`), which the coordinator terminates on abort. The
graph index does not use it.

What is needed, and was not built here:

- **Run each language module's analysis phase in a worker,** coordinated as
  `check` is. On abort, terminate the worker and report the run
  `Cancelled`, with nothing stored for the unfinished phase.
- **Isolation costs memory.** The TypeScript program and its results would
  have to cross the thread boundary or be rebuilt. That should be measured
  on the large pins before it is built.
- **A deadline is a separate question.** With a worker, cancellation becomes
  effective. A time limit would still make results depend on the machine,
  so deterministic bounds such as this one stay the primary guard (C-26).
