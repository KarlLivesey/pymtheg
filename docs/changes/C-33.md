## What changed

An explicit source-only `graph index` can finish after one content inventory.
The inventory must agree with the command checkpoint, including the module
versions and settings. Changed dependency inputs and retryable failures still
request an index. The command checks the checkpoint again in the read snapshot
that supplies the result, so an intervening graph write cannot certify a stale
graph. Injected module registries and the opt-in toolchain use the indexer.
On the verified path, the command reports the inventory and stored counts
without opening an index run or switching the SQLite journal. It emits the
existing completion progress event after verifying the response snapshot.

Each inventory uses one reusable buffer, still opens regular files without
following symlinks, checks the opened handle and hashes its bytes through EOF.
It checks UTF-8 validity as it reads. A file with its previous size and mtime
still goes through SHA-256. An mtime-only change leaves the digest untouched.
A rename over a path or a Git checkout can replace bytes or swap the contents
of two paths, and each path is compared with its own previous digest. This
works on filesystems with coarse timestamps and avoids treating ctime as a
monotonic content version. The installed-declaration input rules from C-22
continue to apply to that separate input set.

The CPU profiles for cli/cli and golang/tools showed repeated compilation
of the same file-claim and context globs. The same pattern compiler still
runs, with a bounded cache of the compiled regular expressions.

On an edit, the indexer compares stored file headers before it reads the full
parse record. It only reads a previous body when it needs details such as the
prior edited file or a failed parse. An unfinished run still rewrites every
file. A missing analysis completion record still forces Go recovery.

The scoped Go resolver receives a compact projection of the stored file
records. It reads path, module, parse status, diagnostic and module facts,
and the embedding links in original parse order. It reads the complete symbol
facts and just the scoped input links as before. Validation looks up the
source, target and candidate IDs named by the result. An invalid ID still
fails validation. Full resolution and modules without a projection keep
their existing reads. The TypeScript resolver declares that it only uses
symbols and links, so it no longer loads project file bodies for resolution.

## SQLite page cache

Cold restic trials used the production store on memory-backed storage. The
two default-cache controls took 158.0 and 125.1 CPU seconds. A 16 MiB cache
took 136.8 CPU seconds, within that spread, and 64 MiB took 105.3. Peak RSS
was 733 and 691 MiB for the controls, 781 MiB at 16 MiB, and 752 MiB at
64 MiB. Follow-up trials at 128 and 256 MiB took 149.2 and 121.3 CPU seconds
and peaked at 804 and 870 MiB. The observations show variation at these
sizes. The 64 MiB trial was the smallest setting that beat both default
controls and had the lowest observed CPU time. RSS includes the resolver
and Node's heap and varies by run.

The writable graph connection uses `PRAGMA cache_size` with a ceiling of
64 MiB and a limit of one sixty-fourth of physical memory or the container
limit, whichever is lower. For example, a 1 GiB container allows 16 MiB.
SQLite fills the cache as it reads pages. Read-only connections keep the
standard cache, as do writable connections when the calculated cap is below
the default or the database already has an explicit cache default. The
connection setting leaves the database header, journal and sync policy alone.
[Cache trial](../../evidence/c-33/cache-knee.json) · [Larger-cache follow-up](../../evidence/c-33/cache-larger.json)

The global index uses an over-inclusive set of method names for each receiver
group. A known struct without embeddings or uncertain variants can be ruled
out when it has no method of the first name required by an interface. Fields
of the same name cannot satisfy that method. Any possible match, embedding,
uncertain method set or build-variant case uses the existing selector and
signature checks. The filter is rebuilt from the same symbol facts and has
no durable representation or additional transaction boundary.

An edited command still checks content before indexing, captures the source
snapshot after the indexer takes its ownership baseline, and checks content
at the end before publishing completion. Sharing the first capture with an
index run started later would let that run use bytes taken before an overtaking
indexer's commit. Go still loads full records for project analysis and
rebuilds global lookup facts for notes and resolution. TypeScript and Rust
still perform their existing whole-module phases when a source changes.

The edited profiles still show SQLite scanning file bodies for its projection
and Go recomputing import providers and method sets. The two Go passes use
different symbol IDs for provisional notes and stored decisions. Completing a
shared or durable cache for those passes needs its own identity and
invalidation proof. The command still imports the language modules up front.
These costs account for most of the remaining gap to the body-edit targets.
