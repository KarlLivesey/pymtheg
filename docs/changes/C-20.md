# C-20 TypeScript library members from installed dependencies

TypeScript uses declarations selected by the compiler from an existing
installation. This can name a member reached through a library return type
or a re-export. The checkout inventory still excludes `node_modules`.
Installed files supply library targets and resolution metadata.

The compiler's resolver reads package manifests, selected package JSON
configuration, and declaration files. This covers `types`, `typings`,
conditional `exports`, `typesVersions`, `@types` fallback, and triple-slash
type references. Implicit ambient discovery lists the direct entries of a
selected `node_modules/@types` directory. The host does no recursive install
walk. Installed JavaScript and TypeScript implementations are excluded.

The host follows package symlinks that resolve within the checkout. This
includes pnpm's in-checkout `node_modules/.pnpm` virtual store and normal
workspace links. Files hard-linked into the virtual store are read at their
checkout paths. Symlinks that leave the checkout are blocked, including npm
links to a different project and pnpm virtual stores configured outside the
checkout. A workspace source already in the snapshot remains checkout code.

For a library member, `declaring-owner` comes from the checker's declaration.
The owning package's manifest supplies its canonical name and installed
version, even through an npm alias. An `@types` declaration names the described
unit and carries the version of the installed type package. The
`versionSource` is the project-relative path to that installed `package.json`.
`package.json` was already approved in `versionFiles`. The indexer accepts
the path only when the module captured the manifest in the dependency
snapshot. A DOM and Node declaration that both remain possible produce
library candidates. A program with a checker-proven single declaration uses
that declaration.

The snapshot records the package manifests, hashes of read declarations, and
stamps for the resolver's probes, including misses. A changed stamp invalidates
the existing TypeScript analysis. A warm graph query checks metadata without
reading declarations. During a rebuild, the resolver reads its requested
inputs and a bounded process-local cache reuses unchanged declaration text.
TypeScript module version 34 triggers re-indexing.

The host bounds individual installed files at 4 MiB and declaration inputs at
32 MiB or 8,000 files per compiler program. A program that exceeds its total
declaration budget reports an incomplete analysis. An unreadable or absent
declaration leaves the ordinary source-only resolution available wherever the
source proves it.

React Hook Form's `page.locator('input[name="lastName"]')` resolves to
`playwright-core` `Page.prototype.locator` at installed version `1.61.1`.
The return and callback types reach Playwright's declaration through the
test package. [Pinned use](https://github.com/react-hook-form/react-hook-form/blob/66f4d72b8c66627d5542dd13e15070227d84d4a2/e2e/basicSchemaValidation.spec.ts#L37)

## Bare comparison

The 18 bare pins match main at **70.42% Level 2**, with 979,195 named or
checkout-resolved links out of 1,390,561. The comparison checked every link
outcome, checkout destination, library destination, candidate and stored
link datum. It found zero changes and preserved all 208,673 symbol keys.
That includes all 1,023,804 definite checkout and library targets. The bare
graphs read five checked-in fixture manifests and zero installed declaration
files. The installed-only extraction fixes leave their links unchanged.
[Per-pin preservation counts](../../evidence/c-20/bare-preservation.json)

A qualified installed type such as `React.FC` uses its exact namespace
declaration. A missing checkout source can still make inferred members
uncertain. An independently written import keeps its package route when
the installed declaration and written route agree. A mapped member such as
`screen.getByRole(...)` keeps its proven package at Level 1 when the checker
cannot identify a named declaring member.

Installed mode adds 141,063 Level 2 links and withdraws 7,000, for a net gain
of 134,063 to reach 1,113,258. All-sites and matched-site results agree.
Checkout symbol keys are unchanged. Pre-merge and post-merge builds have identical compiled
TypeScript modules. The measured stores contain zero indexed Go or Rust files,
so the Go and Rust merges do not change the measured cohort.

`ERESOLVE`. Zod declares `nub`, and T3 Code declares Bun. Those managers are
outside the sweep installer, so the three pins retain their bare figures.

## Remaining limits

Packages that ship no usable declarations still depend on source-only proof.
External linked packages, Yarn Plug'n'Play archives, generated declarations
that need build scripts, and custom pnpm virtual stores outside the checkout
are outside the capture boundary. A cold process builds new TypeScript
programs from resolver-selected inputs after an edit. Warm unchanged graphs
reuse stored facts and only check input metadata. Process-local declaration
text reuse is bounded by the cache size.
