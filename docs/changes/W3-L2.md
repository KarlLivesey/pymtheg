# W3-L2: the Go toolchain opt-in in `pymtheg graph`

W3-L made toolchain-backed Go links available through `indexProject`. This
chunk wires the opt-in into the graph commands (`src/graph/commands.ts`), so
the CLI, and anything else built on `executeGraph`, uses it. Evidence:
`evidence/w3-l2/`.

## What changed

- **The setting.** `executeGraph` reads `.pymtheg/settings.json`
  (`loadConfig`). It passes `graphToolchains(config)`, the toolchain folder
  `.pymtheg/rebuildable/toolchain` and its abort signal to every
  `indexProject` call. No settings file, no `graph` setting, and
  `"go": false` are all off.
  - Off is byte-identical to `main`, both the command output and the stored
    graph (test; restic, evidence). The record's `settings.toolchains` stays
    `"disabled"`, as before.
  - An unreadable settings file is off too, with a `settings-unreadable`
    warning.
- **The completion record.** With the toolchain on:
  - `settings.toolchains` holds the setting, so toggling it changes the
    record's fingerprint and the next query syncs (on → off → on: each one
    syncs).
  - The record keeps the toolchain state, including the key the Go route
    computed its facts from (or `unavailable:<reason>`).
- **The warm path.** A query that would otherwise be answered `unchanged`
  recomputes that key the way the Go module's analysis does. That means
  `go env`, the captured Go files read from disk (their hashes must equal the
  inventory's), then the helper's fingerprint pass.
  - It answers `unchanged` only if the key equals the recorded one.
    Otherwise it syncs: a changed `go.mod` or `go.sum`, a local `replace`
    target, the Go version, the module cache, or Go files the index does not
    capture.
  - If the key cannot be computed, it syncs too. It never gives a stale
    "unchanged".
  - On restic a warm query took 4.1 s on the dev server (3.4 s in an earlier
    run), Node start-up included. A first version that re-synced every query
    took 33.2 s.
  - `graph status` and `--no-sync` do not recompute the key. They report the
    recorded state.
- **Output (additive).**
  - `GraphResponse.toolchain` is present only when the setting is on. It
    reads `{ setting, go: { state: "used" | "unavailable" | "not-indexed", … } }`.
  - When used, it gives the Go version, the configuration, the package
    counts, and the counts of upgraded links, verified sets, confirmed links
    and disagreements. When unavailable, it gives the reason (go missing,
    `go.work`, `go list` failed, …).
  - Text output adds one line, `Toolchain go: …`, to every answer.
  - Every query link the toolchain decided carries `decidedBy: "toolchain"`;
    `origin` stays the link's parse or analysis origin. In text it reads
    `definite (toolchain)` or `candidate-set (toolchain)`. The certainty
    stays as stored; there is no new class.
  - A link the toolchain only confirmed is marked too. Its
    `data.toolchain.from` says what the source-only route had.

## Tests (`test/graph-command-toolchain.test.mjs`)

- **Off:** the same answers and stored graph for no settings file, no
  `graph` setting, and `"go": false`. There is no `toolchain` field and no
  `decidedBy`.
- **On:** `graph index` reports the route, and `status` reports the same.
  `graph callers '(*File).Write'` returns `store.First(files).Write`, which is
  unresolved source-only, as definite with `decidedBy: "toolchain"`. An
  unchanged repeat query answers `unchanged`.
- **On → off → on:** each toggle syncs, and the marks come and go.
- **`go` missing** (an absolute `go` path that does not exist): the index
  succeeds source-only, and `toolchain.go` is `unavailable` with the reason.
- **An edit only the toolchain sees:** a local `replace` target outside the
  project is edited so `A` no longer implements `I`. The inventory does not
  change, and the next query no longer has the pair.

## Limits

- `graph status` and `--no-sync` report the recorded toolchain state without
  checking the toolchain's inputs.
- The key check costs about 1–4 s per warm query on a restic-sized project
  (one `go list`), and only when the toolchain is on.
- Only the Go route exists; `graph.toolchain` has no other language.
- The MCP tools (R1-C) get the behaviour through `executeGraph`. No MCP
  file is changed here.

Owned paths only: `src/graph/commands.ts`, `src/graph/command-toolchain.ts`
(new), `src/graph/command-queries.ts` (the `decidedBy` field), `src/cli/graph.ts`
(output only), the test, this note, `evidence/w3-l2/`.
