# C-32 TypeScript directory imports and checkout file identity

## Relative directories

The snapshot host keyed directories without a trailing slash, while
TypeScript preserved the slash in probes for `.`, `..`, `./`, `../` and
other directory spellings. The false negative caused the resolver to skip
the directory's manifest and index files. tRPC's client resource test and
tanstack-react-query's unstable-handles tests use these spellings.
[C-28 diagnosis](C-28.md#where-the-error-typed-receivers-come-from-installed)

The host now accepts either directory spelling. TypeScript still picks the
entry, including `index.ts`, `index.tsx`, `index.d.ts` and a manifest's
`types` file under Node10, Node16 or NodeNext CommonJS, and Bundler. In
Node16 and NodeNext ESM, the compiler refuses directory imports and the
graph leaves them unresolved with `directory-import-not-allowed-in-esm`
when it can verify the directory entry. The legacy extension fallback uses the
importing file's mode to confirm the same adjacent file when the extension
is supplied. A directory index or package entry cannot use that fallback.
Failed-file attribution uses the same specifier resolution as the edge.

A directory import inside the installed CodeMirror add-on exposes an
augmentation that merges into the original `CodeMirror.EditorConfiguration`
symbol. The graph keeps the original library identity for that merged
symbol and still reaches members supplied by the add-on.

## Checkout package identity and failure containment

TypeScript 5.9.3 deduplicates package source files by package name, version,
package-relative subpath and peer dependencies. The Turborepo examples have
separate workspace copies of `@repo/eslint-config@0.0.0` with a `next.js`
subpath. The workspace resolver found the correct physical paths, then the
compiler redirected the 68-unit copy in `examples/with-yarn` to the
903-unit file in `examples/basic`. The program labelled the redirected
source with the short file's path. Its module range still came from the
long file. [SW-5 diagnosis and reduced replay](https://github.com/KarlLivesey/pymtheg/pull/39)

When resolution selects a captured checkout file, the compiler now uses
the resolved snapshot path as its source identity. Registry declarations
still use TypeScript's package IDs. Duplicate package names do not override
the importing workspace's route, and a name with multiple members in that
workspace requires a separately proved route.

C-13 contained exceptions during compiler work. Here extraction returned
normally and the graph core rejected the range while validating the whole
batch. The TypeScript module checks the extracted ranges against the
captured file before returning them. An out-of-range fact drops that file,
with a diagnostic, through the compiler session's existing rebuild path.
The failed file contributes no symbols and links into it are unavailable.
[C-13 containment](C-13.md#what-changed)

The TypeScript module version moves from 41 to 42 so existing stores
rebuild. Graph symbol keys still use the declaration and its checkout
path.

## Known limits

With `preserveSymlinks: true`, imports through a workspace symlink can
still be stored as `external` even when the compiler selects the importing
workspace's copy. Main has the same behavior.
