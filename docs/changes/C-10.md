# C-10 Rust references to local bindings and method calls on locals

Rust now links three kinds of reference that were unresolved although the
source proves them. Every link that was definite on main keeps its target,
no symbol key changes, and no symbol or link site is added.

## Local bindings and generic parameters

A value or call reference to a local `let` binding, a parameter, a closure
parameter, a pattern binding or `self` targets the enclosing function. The
link records the binding's name and declaration span in `data.localBinding`,
the form TypeScript uses since [C-3](C-3.md). Shadowing follows Rust's rules:
a later `let` shadows, bindings are block scoped, and `if let`, `while let`,
`match` arms, guards, `for` loops and `let … else` bind only in their own
regions. A binding is not proved, and the reference stays unresolved, when:

- a macro invocation could introduce it, or an unknown statement macro comes
  before it in its block (a macro proved to expand to nothing does not count);
- a `#[cfg]` alternative chooses between bindings;
- the name could be a constant, unit struct or unit variant, because Rust then
  reads the pattern as a path, not a binding (`None => None`);
- the reference is in the function's signature or a closure's own parameter
  list, where the parameters are not in scope.

A bare generic type or const parameter (`T`, `N`) targets the item that
declares it, with `data.typeParameter`. Outer generics are not visible in a
nested item, and an associated path such as `S::Item` is not the parameter.

## Method calls on receivers typed from source

A receiver's type is now taken from written declarations, not only from an
annotation: a `let` initialised by a struct literal, by a call with one
definite checkout callee whose return type is written (`Self` resolved through
its impl), by a definite method earlier in a chain, or by a declared field of a
checkout struct; `&`, `*` on a reference, `?` on a written `Result` or `Option`
(directly or through one checkout alias such as `type Result<T = ()> =
std::result::Result<T, Error>`), and `.await` on an `async fn`. The parser
records the receiver expression as a small recipe in the link
(`data.receiverExpr`); the resolver evaluates it with the same lookups and the
same method rules as written receivers. Generic results, closures, iterator
items, pattern bindings, indexing and macros stay unresolved, and the gap is
recorded (`data.receiverGap` from the parser, `data.receiverTyping.gap` from
analysis). A proven standard or dependency receiver type is recorded as
`data.receiverTyping.outside`; its method gets no library target (that is the
`rust-std-receiver` item).

Method selection was definite only at the first probe step. An owned receiver
calling a `&self` or `&mut self` inherent method reaches it at the autoref
step, after every by-value trait candidate (and, for `&mut self`, every
`&self` one). That step is now definite when no such candidate can exist:

- the name is not a by-value method of a prelude trait the type implements or
  derives, nor of a blanket standard trait (`into`, `try_into`; for `&mut
  self` also `to_owned`, `to_string`, `borrow`, …), counting hidden methods
  such as `Eq::assert_receiver_is_total_eq`;
- no checkout trait has a method of that name, and no checkout impl of a
  trait outside the checkout defines one;
- every `use` in scope resolves into the checkout or names a standard trait
  whose methods are known, and a glob import into the checkout is checked
  the same way;
- the type has no written impl of a trait whose methods are unknown, and no
  non-standard derive or attribute macro when the call is in the same file or
  a glob import is in scope (generated code can declare a trait there);
- no unknown macro is in scope and no file in reach failed to parse.

Trait methods (even of a checkout trait implemented for the type), `Box`,
`Rc` and `Arc` receivers, `Deref` targets and reference-to-reference
receivers stay unresolved. The resolver evaluates each recipe once per site
and place and reuses C-1's memoised lookups.

The Rust module version moves from 28 to 29 and stores re-index: function
symbols record their written return type and `async`, structs their declared
fields, and type aliases their parameter defaults.

## What remains

Among unresolved method calls on the ten pins, the receiver's callee had no
single checkout target in 29,677 cases (mostly library constructors such as
`Vec::new`), a chain went through an unresolved method in 11,670, a written
type still could not be closed in 10,171 (trait dispatch, later probe steps,
library types), and pattern bindings, destructuring, closure parameters,
macros, literals, iterator items and indexing account for most of the rest.
2,856 receivers have a proven library type. Trait-method targets and
smart-pointer receivers are the next Rust method steps.

## Tests whose expectations changed

These tests pinned the old outcome. Each now expects the method rustc selects
or the enclosing function of a local binding (never the outer function of the
same name):

- `graph-rust-review`: raw identifiers; blanket trait without `f`; `mut self`
  receiver; lifetimes; generic impl from outside; `impl Tr for &A` with `g`;
  binding regions (locals now target `run`/`arms`); aliased type arguments;
  explicit standard type arguments; an unresolved trait implemented for
  another type (`round 6`).
- `graph-rust-round4`: structural bindings; alias chains; standard blanket
  names (`into`, `try_into` stay unresolved; associated functions and `&self`
  trait methods do not precede the inherent method); fully generic impls; the
  `for` binding; value `self`; alias cache; generic alias.
- `graph-rust-round5`, `graph-rust-round6`, `graph-rust-round7`: autoref on
  typed parameters; the D16 "later probe" control; local bindings in loops,
  guards, or-patterns and closures; the hint-overflow fixture now uses an
  `if let` receiver so its call stays unresolved.
- `graph-rust-rules`, `graph-rust`: typed receivers and locals in the
  negative controls and the sample workspace; the conformance snapshot gains
  eight targets (generic `T`, parameter `value`, `a.own` in `flat.rs`).
- `graph-command-review` and the `mcp-graph` mixed fixture: the
  unresolved-hint example uses an `if let`
  receiver.

Cases that must stay unresolved remain asserted, and the new
`graph-rust-locals-receivers` tests add fd- and just-shaped fixtures and
negatives that `cargo check` proves resolve to a trait method.
