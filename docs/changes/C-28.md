# C-28 TypeScript lookups that had no target symbol

This chunk is a diagnosis. It changes no product code. The coverage plan
lists TypeScript links whose first stored reason is `no-symbol` as its
largest group (172,672 bare and 88,631 installed links, estimated at
9.8–10.9 points). The diagnosis finds almost nothing in that group that the
compiler can prove. That kind of proof is what a definite link needs.
Following the brief, the chunk stops after the diagnosis and reports. The
evidence is in [evidence/c-28](../../evidence/c-28/README.md).

## What `no-symbol` means

The TypeScript module asks the compiler for the symbol at the link's
position. It stores `no-symbol` when the compiler gives back none and no
earlier rule recorded a more specific reason. So the compiler has bound no
declaration at that site. The question for each site was why.

## How the sites were classified

A diagnosis build of main adds one fact to each `no-symbol` link: what the
compiler knows at the site. The patch is
[diagnose.patch](../../evidence/c-28/diagnose.patch). The fact records:

- the form of the site: a bare name, a member, or a callee that is itself an
  expression;
- the type of the receiver;
- whether the receiver's type has the property, and where that property is
  declared;
- the signature the compiler selects for a computed callee;
- for a receiver of the compiler's error type, the origin of the error. The
  build follows the receiver back through variables, destructuring, type
  annotations and call return types to an import whose module has a stored
  reason, or to an undeclared name.

The build changes nothing else. On all 18 finished attempts (10 bare, 8 installed; Zod's installed attempt was unavailable), its counts of
resolution × reason per pin are identical to main's.

The pins are Hono, tRPC, Zod, Astro, Vitest, Redux Toolkit, Nest,
PocketBase, Puppeteer and Dexie, at their sweep commits. All ten ran bare.
Eight also ran installed; Zod's package manager is unsupported, and
PocketBase is a Go pin in the manifest. Main is `5364e87`.

`ambiguous-project`.

## Out of reach, and why

- **error-receiver:** the compiler binds nothing until the upstream module
  resolves. A link here could only be a guess.
- **undeclared-name and its chains:** the owning program does not declare
  the name. A test runner may declare it at run time, but the compiler
  configuration does not.
- **returned callables and immediately invoked functions:** the compiler
  selects a call signature of an anonymous function or of a type, not a named
  declaration. A signature from a `typeof` annotation also does not prove
  which value runs.
- **undeclared members:** no declaration exists. Some lines say so with
  `@ts-expect-error`.

## Found but not built

- **Calls through a constant symbol key.** Examples are
  `this[disposeSymbol]()`, `super[asyncDisposeSymbol]()` and
  `session[PERSIST_SYMBOL]()`. The key's type is one unique or well-known
  symbol, and the receiver declares one method with that key. That is a
  provable member call, like a string-literal key. Installed, 97 computed-key
  calls select a named checkout method. About 70 of them use a constant
  symbol key (list in the evidence). That is roughly 0.01 points, so it is
  not built here.
- **Nest's test configuration.** `packages/platform-node/test` and
  `packages/platform-ws/test` have no test config of their own. The graph
  gives these spec files to `packages/tsconfig.build.json` (types `node`),
  because it is the deeper config. Root `tsconfig.spec.json` also includes
  them, with `vitest/globals`. About 5,000 installed links depend on that
  choice: 2,863 undeclared test globals and 2,116 chains rooted at them. This
  belongs to configuration selection (`ts-ambiguous-project`), not to
  `no-symbol`.
- **The plan's installed figure for this group** uses bare results where an
  installed attempt did not finish. Those pins are Nest (28,127 links, whose
  install failed in SW-4), PocketBase (18,984), T3 Code (9,329) and Zod
  (498): 56,938 of the 88,631. Main now installs Nest. Nest's installed
  `no-symbol` count is 6,672, and its installed Level 2 is 91.55%, against
  the 74.78% bare figure the plan used.
- **Precise reasons.** The classes above could replace `no-symbol` with
  stored reasons such as `error-receiver` carrying the upstream reason,
  `undeclared-name` and `anonymous-callee`. The plan would then credit
  these links to the items that fix them. Coverage would not change, and
  the plan's item mapping is about to be replaced by pull request 34.
  This is left for the manager to schedule with that plan.
