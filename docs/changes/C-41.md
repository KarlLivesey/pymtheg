# C-41: TypeScript members of object and type literals as link targets

The installed sweep (SW-6) stores 43,168 TypeScript links as unresolved
with reason `local`: the checker names a declaration, and the module has no
symbol for it or refuses it. C-41 measures that group by declaration kind
and by where the literal lives. It then makes members of written type literals link targets, under one
product rule: never a wrong definite link. A member call links definitely
only when every step of its receiver is a kind the walk proves to have one
producer (listed below, "The step kinds that can give a definite link");
any other step leaves an object- or type-literal member unresolved. An
interface or class member keeps the checker's answer when the walk
cannot follow the receiver (one declaration whatever the producer), and
becomes a candidate set only when the walk enumerates distinct producers
(`pick ? ia : ib`). Applied to every member call, this turns some of
main's definite links of reduced shapes into candidate sets.

TypeScript module version 50 here, provisional: main is at 49; if another chunk
merges first with 50, this one moves to the next.

## Which declarations become symbols

- **Members of a type literal written in a type position.**
  - The type of a module-level declaration or of a class or interface
    member: `export type Api = { query(): void }`, `declare const api: {
    m(): void }`, `interface Holder { inner: { q(): void } }`. Main had
    symbols for many of these (4,158 refused calls) and refused calls on
    them. C-41 lets calls link to them.
  - Nested type positions, each with its place in the identity: a union
    arm `[|i]`, an intersection part `[&i]`, an array element `[]`, a
    tuple element `[#i]`, a type argument `[<i>]`. For example
    `both.[type].[&1].stop` for `declare const both: { run(): void } & {
    stop(): void }`.
  - A named parameter's written type, when the function is a graph symbol:
    `render.[param:db].[type].getConfig` for `function render(db: {
    getConfig(): number })`.
  - Inside a function body, the same positions on declarations that are
    already symbols there: a local variable's written type
    (`inBody.[local].v.[type].lv` for `const v: { lv(): void } = …`) and
    a local function's parameter types
    (`inBody.[local].inner.[param:p].[type].ip`). Calls through these
    written types link like module-level ones and are kept: the identity is
    the body's `[local]` name path, not a position in the body, so other
    edits to the body do not move it.
  - A type literal's overloads (`{ run(): void; run(x: number): void }`)
    are one symbol, at the first signature, as an interface's are.
  - The place segments `[|i]`, `[&i]`, `[#i]` and `[<i>]` are indexes:
    inserting a union arm (or an intersection part, tuple element or type
    argument) before another shifts the later ones' identities, as
    reordering them does.
- **Not symbols:**
  - Destructured bindings, untyped locals and parameters, and local type
    aliases and interfaces (`type L = { … }` inside a function). A call
    through a local alias stays `local`.
  - Object-literal members passed as call arguments or built inside a
    function: they have no anchored owner, and a call through a generic
    (`setup({ hydrate() {} }).hydrate()`) cannot prove which literal
    produced the value.
  - Index signatures and mapped types: no named member exists.

Symbols per pin are in "Before and after" below.

## When a member call links: every step of the receiver proven

The checker's declaration for `receiver.member` names the member of the
type it computed for the receiver. When a value comes from several producers
(`pick ? one : two`, `a ?? b`, an array literal's element, an inferred
return with several `return`s), the checker forms their union with subtype
reduction. Structurally identical types reduce to one arm, and the
declaration list then names that arm's member only: a wrong definite link
when the other arm was chosen. This holds for every kind of member, so the
rule covers interface, type-literal, class and object-literal members
alike. Main had such wrong links for interfaces
(`ichosen = pick ? ia : ib; ichosen.run()` → `IA.run`) and object literals
(`formats = [csv, tsv]; formats[1]!.format()` → `csv.format`).

So the receiver's chain is walked to its producers, step by step
(`receiver-arms.ts`). Each value resolves to its *arms*, the types of the
producers it can come from:
- A conditional, `??` and `||` have both sides' arms. A left side of `??`
  that is never nullish, or of `||` that is only objects, is the value.
- An array literal is one arm whose elements an element access walks: a
  literal index picks that element (`formats[1]` is `tsv`), any other
  index, a `for…of` variable and the first parameter of an array method's
  callback (`forEach`, `map`, `filter`, `find`, `some`, `every`,
  `flatMap`, …) have every element's arms.
- A name has the arms of its declaration: a `const`'s initialiser; a `let`
  or `var`'s initialiser and every value assigned to it (in its own file,
  which is the only place a module's binding can be assigned; a script's
  top-level `var` or `let` is not followed); a destructured binding, the
  property or element of its source's arms (a default only where the value
  can be `undefined`).
- A property has the arms of the member's declaration on each arm: an
  object literal's property or a class property without a written type its
  initialiser and every plain assignment to it in the program (see the
  step kinds below for what is not read); an object literal's
  member, its last own property or the spreads after it.
- A call to a function with an inferred return type has the arms of its
  `return`s. A chain of single-`return` functions is followed without
  recursion, as the checker itself infers it.

A step is one arm, the checker's own type there, when its type is
*written*: a declaration with a type annotation (an ambient one too, such
as `Date`), a module, namespace, class, function, enum or method, an
assertion (`x as T`), `this`, a literal, a `yield`, or a call or tagged
template whose signature writes its return type. A written type is not
itself a reduction; a generic one instantiated from inferred arguments is
handled below. A primitive literal arm is its primitive (`"a"` and `"b"`
are one `string` arm: no member differs). Several steps need more:
- A union only loses an arm the checker finds assignable to another
  (subtype reduction), so arms none of which is assignable to another are
  not reduced (`[z.string(), z.number()]`). Assignability is wider than
  the subtype relation, so this errs towards "reduced".
- A generic call (`createApi(config)`) whose type arguments are inferred
  is one arm when its arguments are unreduced. When they may be
  (`expect(pick ? a : b)`), the result keeps its declared type beside the
  instantiated one, and a member is taken from it only when the declared
  type has the same member: `expect(…).toBe` is `Assertion<T>`'s own
  member whatever `T` became, while `same(pick ? a : b).util` reaches
  into `T` and is unresolved. A generic function with an inferred return
  type is handled the same way, through its signature, when its body's
  returns are not a reducible union.
- A member of an instantiated generic type, or a method of an instantiated
  generic class, whose declaration has no written type
  (`get shape() { … }`, `unwrap() { return this.inner; }`): its body is
  in the generic's terms, so it only has to show that no reducible union
  forms there; the value is the instantiated member's
  (`NonOpt<Opt<number>>.unwrap().unwrap()` → `Opt.unwrap`).
- An untyped callback parameter typed by a generic call the walk cannot
  prove unreduced (`configureStore({ middleware: (gDM) => gDM().concat(…)
  })`) keeps its type as the call's uninstantiated signature declares it,
  followed through object properties and returned functions, under the
  same rule: `gDM().concat` is the container's member, while
  `run(pick ? c1 : c2, (x) => x.m())` reaches into `T` and is
  unresolved.
- A call without a signature declaration (`require` in JavaScript) is one
  arm.
- An untyped parameter of a function expression gets its type from the
  context: it is one arm when the function is an argument of a call whose
  callee is one arm and whose instantiation passes the check above, the
  initialiser of a declaration with a written type, a property of an object
  literal in such a context, a JSX attribute, an assignment's value, or
  returned from a function with a written return type.

Anything else (an expando assignment, a `let` written by destructuring or
`++`, a generic body with several returns) cannot be followed, and the
call is unresolved (`receiver-unverified`). The walk keeps the checker's
type after a step only when its single arm is the checker's own type at
that step, so flow narrowing is kept and a reduction is not.

Before the member is looked up, the arms are split into their union
parts and filtered by the checker's own type at the receiver, which
control flow may have narrowed (`typeof r === "string" ? r :
r.toString()`, `instanceof`). A part is kept when it is assignable to
that type (a primitive part when that type has a primitive of its kind).
A reduction keeps every arm, since each is assignable to the one the
checker kept; narrowing drops the parts it excluded. If the kept parts are
exactly the checker's type, its answer stands, and so it does when no part
is kept: a reduction always keeps an arm the checker's type holds, so a
type none of the arms is assignable to comes from a narrowing the walk
does not see (a conditional type narrowed by `typeof`). This keeps a contextual
`this` (an object literal's method typed by an interface) on the
interface's member.

The member is then looked up on each arm. If the arms' members are the
checker's member, its answer stands. If not, they replace it: a candidate
set when there are several (`pick ? one : two` gives `one.run` and
`two.run`), the right single member when the checker named a wrong one
(`formats[1]!.format()` → `tsv.format`). An arm without the member, or an
arm member with no symbol (a literal in a function type's return), leaves
the call unresolved (`reduced-receiver`, or `multiple-object-producers`
when an object literal's member is among them). Main's producer check for
unanchored object-literal members still runs after this, unchanged.

The walk reads only declarations the checker's symbols name, the files the
receiver's chain already depends on for type checking. A type-literal
member's link no longer needs the receiver's declaration to write the type
that holds the literal (the first version of this chunk): a receiver typed
through a generic call with one-arm arguments, or through an inferred
return with one `return`, links too.

### The step kinds that can give a definite link (review round 2)

The walk denies by default. A receiver links definitely only when every
step of its chain is one of these, and the step's producers are one arm or
are enumerated to a candidate set. Any other step leaves the call
unresolved (`receiver-unverified`):
- **Written:** a declaration with a type annotation (an ambient one too),
  a module, namespace, class, function, enum or method, an assertion, `this`,
  a literal, `yield`, or a call or tagged template whose signature writes
  its return type and whose type arguments are written or proven
  unreduced.
- **Choices:** a conditional, `??` and `||` (one side when the other can
  never be the value), `&&`, a comma, an assignment's value. `??=` and
  `||=` as `??` and `||`, `&&=` as `&&` (review round 3). Without
  `strictNullChecks` a type never shows `null` or `undefined`, so `??`
  and `||` always take both sides. Any other operator is followed only
  when its value is a primitive.
- **Names:**
  - a `const`'s initialiser;
  - a `let` or `var` with its initialiser and every assignment in its file
    (`=`, `??=`, `||=`, `&&=`; any other write is not followed);
  - a destructured binding, as the property or element of its source,
    with a default only where the value can be `undefined`.
- **Parameters:**
  - an untyped one of a function expression typed by a written context,
    or the first parameter of an array method's callback (each element);
  - a defaulted one of a plain function that is not exported and whose
    every use in its file is a direct call: the default and every call's
    argument. Any other reference to the function is an escape: an export
    specifier (`export { f }`), a shorthand property (`export default { f }`,
    `const api = { f }`, `module.exports = { f }`), and any reference the
    checker cannot place (review round 3).

  A defaulted parameter of a method, a constructor or an exported
  function is not followed.
- **Members:**
  - a property of each arm;
  - an accessor: its getter's returns, with or without a setter, in a
    class or an object literal; a setter without a getter is not followed
    (review round 3);
  - an untyped class field or object-literal property: its initialiser
    and every plain assignment (`=`, `??=`, `||=`, `&&=`) to that member
    by name anywhere in the program. A compound write, a write through a
    computed key to an object that has the member, and
    `Object.assign(target, …)` with such a target leave it unresolved
    (review round 3; before, the computed-key check compared symbols and
    never fired). A write through `any` (`(state as any).h = two`) is not
    seen, and keeps main's answer (a limit, below).
- **Arrays:**
  - an array literal's element: the literal index's element, or every
    element;
  - `for…of`;
  - on an array whose elements have reducible producers, only `find`,
    `findLast`, `at`, `pop` and `shift` (an element) and `filter`,
    `slice`, `sort`, `reverse`, `toSorted` and `toReversed` (an array of
    them). Every other method, iterator or conversion (`values`,
    `entries`, `reduce`, `Array.from`, `new Set`) is not followed.
- **Calls:**
  - a plain function's `return`s;
  - a generic call whose arguments are unreduced each and together
    (arrays counted by their elements, function arguments by their
    returns).

  An open type parameter of a generic body never supplies a member: a
  generic helper's `return { current }` gives the instantiated member
  (`useStore(plain).current.get` → `plain.get`), and an arm whose type is
  still the body's type parameter leaves the call unresolved (review round
  3).

  Otherwise a generic call's result keeps its declared type beside it,
  through `await` and into its methods' callbacks. Only the container's
  own members are taken from it (`expect(…).toBe`); a member reached
  through the inferred type argument is unresolved.

- **Also counted as producers:** values written into an array after it is
  created (`push`, `unshift`, `splice`, `fill`, an element assignment) in
  its file; the spreads of an object literal after its last own property
  of the name (`{ ...defaultHooks, ...opts }`); `x as const` is the value
  of `x`.

**A receiver the walk cannot follow** leaves a member of an object or type
literal unresolved, since each producer has its own declaration. A member
declared on an interface or a class, or in a library, is one declaration
whatever producer supplied the value, so the checker's answer stands
(reviewer B: about 219 links on six pins, `Unsubscribable.unsubscribe`,
`StoreApi.getState` and others, were right on main). Distinct interfaces
reached through arms the walk does follow (`pick ? ia : ib`) still give a
candidate set.

A result computed while the walk hit its depth limit or a cycle is not
cached, so it cannot depend on which call site was walked first. The walk
counts member calls walked and expressions computed
(`receiverStatistics`).

### Limits (review round 3)

Five shapes keep the checker's answer, which can be one member of two
producers:
- **Narrowing to an intersection.** A type guard (`tagged(x)`), an
  assertion function, or `"tag" in x` where neither producer declares
  `tag` narrows `pick ? one : two` to the checker's reduced type
  intersected with the tag, and the walk keeps that narrowing as it keeps
  `typeof` and `instanceof`: `if ("tag" in x) x.run()` gives `one.run`.
- **`require` of a conditional `module.exports`.** In JavaScript,
  `require("./paths").join()`, where `paths.js` sets `module.exports =
  pick ? posix : win`, takes the checker's type of the `require` call:
  `posix.join`.
- **Written types derived from inference.** `typeof x`, `(typeof
  list)[number]` and `ReturnType<typeof make>` are written types, so a
  value declared with one is taken as written. Over two producers the
  written type is the checker's reduction: `declare const p: (typeof
  list)[number]` with `list = [one, two]` gives `p.run()` → `one.run`.

- **An array mutated through an alias or a parameter.** The walk reads
  mutations of the array's own name in its file: `const alias = list;
  alias.unshift(two)`, or `add(list)` with `function add(xs) {
  xs.push(two) }`, is not seen, and `list[0]!.run()` keeps main's
  `one.run`.
- **A member written through `any`.** `(state as any).h = two` has no
  symbol to match, so `state.h.run()` keeps main's `one.run`.

None of the first three is a one-line deny: each would also unresolve the correct links of
the same shape (a guard over one producer, a `require` of a plain
`module.exports`, `typeof` of a single value). `strictNullChecks` off
was one, and is denied (above). Denying the last two would unresolve every
array passed to a function and every member whose name is written
through `any` somewhere in the program.

### Work bounds (review round 3)

A member call's walk stops, unresolved, at 20,000 steps or at 200 nested
steps; `receiverStatistics` counts calls cut by each. A step is an
expression or declaration computed; a cached result is charged what it
cost when computed, so the count, and the outcome, do not depend on what
earlier calls cached. Results touched by a cycle are not cached, which
made the work exponential before (reviewer B: 327,679 expressions for a
self-assigned `let` under 16 nested choices); the step budget bounds it.
The depth limit was 2,000, which the V8 stack reached first: a 520-step
alias chain was resolved or not depending on what the process had indexed
before and on how deeply the call was nested. At 200 the walk's own
recursion cannot exhaust the stack, and a stack overflow anywhere in the
walk is no longer caught there: it reaches the extraction, which rebuilds
the program and records the node as `compiler-limit` (as for any checker
overflow), so it never yields a definite link and never leaves the checker
in a state that changes later answers.

## Found, not built

- **Shapes the walk follows as written but should not** (review round 2,
  further work): a spread of a choice (`{ ...(pick ? one : two) }.run()`,
  whose object literal is taken as written); a parameter written
  `typeof one` and called with `two` (a written type naming a value's
  type); a `Map` built with `one` and later `.set("b", two)` (container
  mutation through a method).
- **Receivers the walk cannot follow** (248 links that were definite on
  main, now `receiver-unverified`; see the audit): a `let` assigned
  inside a callback, a function parameter returned through two calls (a
  tRPC link's `next`), `describe.each`'s table parameter, a `let`
  assigned from itself. Following assignments in nested functions and
  contextual parameters through more call shapes would recover them.
- **Members in a function type's return.** `(pick ? f1 : f2)().run()` with
  `f1: () => { run(): void }` has two arms whose members have no symbol (a
  function type's return is not a symbol position): unresolved
  (`reduced-receiver`) rather than a candidate set.
- **Narrowing after a walked choice.** `const c = pick ? a : b; if (isA(c))
  c.run()` gives both members: the walk does not narrow its arms, so the
  set is sound but wider than the narrowed type.
- **References.** The walk runs for calls. A member read that is not
  called (`const f = chosen.run`) keeps the checker's answer.
- **Receivers typed through a generic's inference with reduced
  arguments**: unresolved, as the walk cannot instantiate the generic for
  each arm.
- **Object-literal members passed to generic calls** (758 on the pins):
  need a symbol for a literal in a call argument and a producer proof
  through the call (`createApi({ run() {} }).util.run()` stays `local`).
- **Symbols in generated files.** The module has no classification of
  generated files, so type literals in t3code's generated schemas get
  symbols like any other file's; the listing order above keeps them from
  displacing other symbols.

## With the scoped re-index (C-38, pull request 50)

The walk reads other files than the one it extracts: the declarations the
receiver's chain names, their initialisers, a `let`'s assignments in its
file, a function's `return`s and the locals they name, `for…of` heads,
callback contexts, and the checker's types at those nodes. C-38's scoped
path, which extracts only an edited file, must count every such read in
the edited file's surface. C-38 is being redesigned so that every read of
another file's text, syntax or body-local checker types goes through one
accessor that records it (part B of pull request 50). The walk will read
through it. Until then the two do not meet: main has no scoped path (part
A, pull request 68, only claims the store early), and pull request 50
does not merge before the redesign.
