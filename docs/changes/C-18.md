# C-18 Rust macro identity beside a name lookup

Rust scope retries can distinguish a built-in derive or attribute from a
similarly named declaration, and follow a macro path to its Cargo dependency.
They apply the existing C-12 expansion bounds after establishing the binding.
Checkout proc-macro bodies still need a supported output proof. The same
`rust-external-macro-name` assumption applies to eligible outside macros.
[C-12](C-12.md)

## Identity rules

- A type, trait, value or bang macro named `Debug` does not bind the
  derive. `std::fmt::Debug` and `core::fmt::Debug` export the standard
  trait and derive under the shared name. `#[derive(...)]` must itself
  refer to the standard attribute before its payload is used for proof.
  The controls import both the standard and a distinct user derive and
  verify their different outputs. [Rust namespaces](https://doc.rust-lang.org/reference/names/namespaces.html#sub-namespaces) · [Rust imports](https://doc.rust-lang.org/reference/items/use-declarations.html)
- Rust reserves `cfg` and `cfg_attr` in the attribute sub-namespace. An
  imported proc macro named `inline` makes unqualified `#[inline]` fail
  with E0659. `test` and `derive` can instead bind an explicit attribute
  import or a matching `#[macro_use] extern crate` export. `macro_rules!
  test` is a bang name. The graph can inspect a captured macro-use crate's
  exports and keeps an uncaptured competing macro-use binding open.
  A tool attribute's first segment is a type-namespace lookup. An
  explicit `rustfmt` crate alias can replace the tool prelude name.
  [Rust macro lookup](https://doc.rust-lang.org/reference/names/name-resolution.html#macros) · [Rust preludes](https://doc.rust-lang.org/reference/names/preludes.html)
- A glob-supplied macro or qualified path head that competes with an
  active outer binding is an ambiguity error in rustc. The controls
  exercise `Debug`, `test`, `derive`, a tool namespace and an extern
  prelude crate name. A glob whose target is captured still participates
  in ordinary member lookup, including `self::Name`. An uncaptured glob
  stays open when no outer binding establishes the name. Macro-generated
  rebindings of the written derive also produce E0659. No separate glob
  assumption is introduced. [Glob ambiguity](https://doc.rust-lang.org/reference/names/name-resolution.html#r-names.resolution.expansion.imports.ambiguity.glob-vs-outer) · [Expansion ambiguity](https://doc.rust-lang.org/reference/names/name-resolution.html#r-names.resolution.expansion.macros.ambiguity.more-expanded-vs-outer)
- A qualified external macro keeps its Cargo unit through a renamed
  edge. Its written exported name may be a re-export, as in Serde or
  Tokio. Named imports use that same lookup. The macro namespace checks
  for Serde and Clap derives, Tokio attributes, rstest attributes and
  bitflags use known registry releases and positive feature evidence to
  recognize namespace facets. Ordinary link
  lookup uses its original scopes. [Serde derive re-export](https://docs.rs/serde/1.0.229/src/serde/lib.rs.html) · [Tokio macro re-exports](https://docs.rs/tokio/1.54.1/src/tokio/lib.rs.html) · [Bitflags declaration](https://docs.rs/bitflags/2.13.2/src/bitflags/lib.rs.html) · [rstest re-exports](https://docs.rs/rstest/0.28.0/src/rstest/lib.rs.html) · [Clap derive re-exports](https://docs.rs/clap/4.6.7/src/clap/lib.rs.html)

- A registry facade must resolve both itself and the implementing crate
  to registry sources. The Cargo lockfile must record the implementing
  crate on the selected facade's dependency list when the implementation
  is known. For uncatalogued exports, the graph checks the dependency
  chain for unverified sources. Cargo patches can replace transitive
  dependencies, including the implementation behind a renamed facade.
  The graph also checks overrides from captured Cargo
  configuration. Once the registry sources are established, a macro
  written through a qualified path or explicit named import identifies
  the export in compiling code. Feature evidence can identify namespace
  facets, including features Cargo unifies across simultaneously active
  dependency edges to the same locked release. [Cargo patch semantics](https://doc.rust-lang.org/cargo/reference/overriding-dependencies.html) · [Cargo feature resolver](https://doc.rust-lang.org/cargo/reference/features.html#feature-resolver-version-2) · [Cargo configuration overrides](https://doc.rust-lang.org/cargo/reference/config.html#patch)

The Rust module version is 38. Existing stores reindex with the updated
identity rules. The capture uses the existing attribute and invocation
facts, and the production graph emits its original sites.
